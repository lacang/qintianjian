# v123 阶段二 · 第一步样例：六份 AI 协作资料包

这六份是**真实排盘/抽牌数据**跑出来的资料包，不是示意图。目的是先验证「资料包本身好不好用」，再谈面板。

生成方式：`node tools/ai-pack-sample.mjs`（可重复生成，内容确定性一致）
数据组织：`app/js/aipack.js`（纯函数，零依赖，浏览器/Node 同构）

## 六份文件

| 文件 | 模式 | 要回答的问题 |
| --- | --- | --- |
| `liuyao-quick.txt/.json` | 快速解读 | 我想快速理解这一盘 |
| `liuyao-classic.txt/.json` | 古法推演 | 我想知道传统规则如何推导 |
| `liuyao-research.txt/.json` | 深度研究 | 我想研究不同规则之间的关系 |
| `tarot-quick.txt/.json` | 快速解读 | 同上，塔罗 |
| `tarot-classic.txt/.json` | 古法推演 | 同上，塔罗 |
| `tarot-research.txt/.json` | 深度研究 | 同上，塔罗 |

`.txt` 是直接粘给大模型的文本，`.json` 是结构化版本。**两者由同一份资料包对象渲染，不是两套拼装逻辑。**

## 三模式到底差在哪（不是字段多少，是问题不同）

六爻：

- quick：完整排盘事实 + 3 条最高权重依据 + 2 条问事域引文
- classic：完整排盘事实 + 全部 4 条依据 + 全部 5 条引文
- research：classic 全部 + 9 个问事域的用神取用对照（含「不另取六亲」的域）

塔罗：

- quick：只给本张牌**实际正逆位那一套**牌义（另一套明确标 not_included）
- classic：正位/逆位两套牌义都给，便于核对取用
- research：classic 全部 + 每张牌正逆位读法对照 + 牌阵全部位置（含未占位）

**任何模式下 `chart_data` 都逐字节一致**（`tools/ai-pack-sample.mjs` 有断言守着）——精简可以少给资料，不能改原始事实。

## 八条检查重点对应位置
