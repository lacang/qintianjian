#### 汇总（逐项加总，非估算）

| 性质 | 01 | 02 | 03 | 例数 | 占比 |
|---|---|---|---|---|---|
| 真独立断言（预期来自被测代码之外的独立来源） | 478 | 2226 | 119 | **2823** | 62.1% |
| 半重复（同一基础数据换断言维度） | 0 | 64 | 0 | **64** | 1.4% |
| 重复（同一事实多次断言） | 120 | 768 | 0 | **888** | 19.5% |
| 派生（依赖其它断言的结果，无新独立事实） | 0 | 768 | 0 | **768** | 16.9% |
| **合计** | **598** | **3826** | **119** | **4543** | 100% |

> 验算：478+2226+119 = 2823；0+64+0 = 64；120+768+0 = 888；0+768+0 = 768；四者相加 = 4543 ✅

#### 这个分布意味着什么

1. **覆盖率应看「独立事实数」，不看「用例数」。** 4543 个用例对应的独立断言约 **2823** 个。说「4543 个用例全绿」是准确的，但说「4543 个独立验证点」会高估 38%。

2. **重复断言不是无效的。** 世应 384 例虽然只有 64 个独立事实，但它能定位到「哪一卦哪一爻」出错；而如果只写 64 例，失败时仍要再查一遍。冗余的价值在**定位精度**，不在覆盖率。

3. **真正的薄弱环节不在重复，而在「预期来源的独立性」。** 最硬的一批是：节气（astronomy-engine 独立算）、干支（JDN 公式）、纳甲（手写口诀表）、八宫（变爻规则现场生成）。这些都不 import 被测代码。相对软的一批是：六亲、变爻纳甲、藏爻干支——它们复用被测层已确认的上游结果，一旦上游错就会**一起错、一起绿**。

4. **本轮的两处修复恰好都落在「硬」区**：藏爻阴阳比对的是标准卦画（外部给定），雷火丰比对的是八宫变爻规则（现场生成）。所以这两条修复的证据强度是够的。
