## 第一章　L0-002 · 八纯首卦藏爻阴阳错位

### 1.1 根因重新裁定（推翻上轮审计结论）

上轮 `l0-fact-audit/10_recommendations.md` 的 P1 项写的是：

> 「`BAGUA_BITS` 表里兑/震/巽/艮 四个卦的阴阳位写反了，应改表」

并给出改表方案：

```
现状（错）→ 应改为
  兑: [false,true,true]   →  [true,true,false]
  震: [false,false,true]  →  [true,false,false]
  巽: [true,true,false]   →  [false,true,true]
  艮: [false,false,true]  →  [false,false,true]     ← 前后同值
```

**这个结论是错的，而且当时自己就露出了破绽**：艮卦的「修正前」与「修正后」写成了同一个值 `[false,false,true]`，说明作者并没有真正核对数组位序，只是把「期望的卦画」硬套进「当前的表」。指令据此提出质疑，本轮按要求重新核了 6 件事，结论完全反转。

#### 6 项前置确认（逐条给结果）

| # | 待确认 | 实测结果 |
|---|---|---|
| 1 | `BAGUA_BITS` 每一位对应哪一爻 | **index 0 = 三爻（上爻）**，index 2 = 初爻。top-to-bottom。 |
| 2 | 数据约定自下而上还是自上而下 | **自下而上（top-to-bottom 存储）**。三处独立佐证见 1.3。 |
| 3 | `paipan.ts` 如何消费该数组 | `bits[i % 3]`，其中 `i` 是 `getFullNajia()` 的索引，**i=0 是初爻**（bottom-to-top）。→ **消费方向与存储方向相反，这才是 bug。** |
| 4 | `getShouGuaPan()` 如何生成藏爻 | `getFullNajia(gong, gong)` 生成六爻纳甲（下卦=初~三，上卦=四~上），阴阳直接取 `bits[i % 3]`。 |
| 5 | `formatCopyText()` 是否使用同一结果 | **不使用。** 复制文本的藏爻段走 `formatCopyText` 自身的 `lineOf()` 渲染，只消费 `getShouGuaPan().yaoList[].yinYang`，不重复计算，因此修一处即全链路一致。 |
| 6 | `XIANTIAN_LINES` 的实际定义及爻序约定 | `timecast.ts:49-58` 八条全对，且 `timecast.ts:112` 注释明确 `lines = [...lower, ...upper]; // index 0=初爻 … 5=上爻`。**它按 bottom-to-top 存**，与 `BAGUA_BITS` 的 top-to-bottom 恰好相反——这正是混淆的来源。 |

#### 双口径实测（决定性证据）

把 `constants.ts` 的 `BAGUA_BITS` 原文用正则解析出来，分别按两种约定读，与标准卦画（初爻→上爻）比对：

| 宫 | 表原始值 | 按 index0=初爻读 | 按 index0=上爻读 | 标准卦画 | B2T? | T2B? |
|---|---|---|---|---|---|---|
| 乾 | `[1,1,1]` | 111 | 111 | 111 | ✅ | ✅ |
| 兑 | `[0,1,1]` | 011 | **110** | 110 | ❌ | ✅ |
| 离 | `[1,0,1]` | 101 | 101 | 101 | ✅ | ✅ |
| 震 | `[0,0,1]` | 001 | **100** | 100 | ❌ | ✅ |
| 巽 | `[1,1,0]` | 110 | **011** | 011 | ❌ | ✅ |
| 坎 | `[0,1,0]` | 010 | 010 | 010 | ✅ | ✅ |
| 艮 | `[1,0,0]` | 100 | **001** | 001 | ❌ | ✅ |
| 坤 | `[0,0,0]` | 000 | 000 | 000 | ✅ | ✅ |

```
按 index0=初爻（bottom-to-top）解读：4/8 正确
按 index0=上爻（top-to-bottom）解读：8/8 正确
```

**表本身 8/8 全对。** 错的只有消费方。

#### 为什么恰好错 4 个宫（数学必然）

兑 110 / 011、震 100 / 001、巽 011 / 110、艮 001 / 100 —— 这四卦的两种读法互为镜像，结果相反。
乾 111、离 101、坎 010、坤 000 —— 这四卦是回文串，正读反读同值，两种约定下都不暴露。

所以「4 个宫错、4 个宫对」不是巧合，而是位序错误在这种对称性下的必然表现。上轮报告观察到「4 个卦错」这个现象是对的，但把原因安到了表上。

#### 三处独立佐证「表是 top-to-bottom」

1. **`liuyao-core/stress-test.ts:73`** 注释原文：
   > 「`BAGUA_BITS` 实际是 `[三爻,二爻,初爻]`（top-to-bottom），`yaoValues` 需要 `[初爻,二爻,三爻]`（bottom-to-top），所以要 reverse。」
   
   第 77-78、92-93 行确实写着 `const lowerBits = [...BAGUA_BITS[lower]].reverse();`。**若按上轮建议改表，这个文件立刻出错。**

2. **`timecast.ts` 的 `XIANTIAN_LINES`** 是另一张表，按 bottom-to-top 存，且注释写明「index 0=初爻」。两张表约定不同、各自自洽——恰恰证明「约定不统一」是这个代码库的真实陷阱。

3. **`getShouGuaPan` 的现有注释** 写「六爻阴阳直接取经卦三爻表（下卦=初~三，上卦=四~上）」——意图是对的，实现反了。

## 第二章　L0-001 · 雷火丰归魂标记

### 2.1 采用的方案：B（回归古法）

雷火丰按八宫生成规则是**坎宫第六卦（五世卦）**，不是归魂。归魂是第八卦地水师。

**坎宫八序（由变爻规则现场推出，非查表）**：

| 位次 | 卦名 | 生成规则 | 世应 |
|---|---|---|---|
| 1 | 坎为水 | 本宫（八纯） | 世6 应3 |
| 2 | 水泽节 | 初爻变（坎010 → 兑110） | 世1 应4 |
| 3 | 水雷屯 | 初二爻变（→ 震100） | 世2 应5 |
| 4 | 水火既济 | 初二三爻变（→ 离101） | 世3 应6 |
| 5 | 泽火革 | 加四爻变（上卦坎 → 兑） | 世4 应1 |
| 6 | **雷火丰** | 加五爻变（上卦 → 震） | **世5 应2** |
| 7 | 地火明夷 | 游魂：五世四爻再变（上卦 → 坤） | 世4 应1 |
| 8 | 地水师 | 归魂：游魂内卦复本宫（下卦离 → 坎） | 世3 应6 |

古法依据：《增删卜易·归魂游魂章》「归魂卦为各宫之第八卦」。

原代码的问题正是**标签与世位自相矛盾**：`isGuiHun = true`（暗示归魂，应世三应六）却同时是 `shiPosition = 5`（世五应二）。这是不可能同时成立的状态，属显示错误，不是流派分歧。

## 第三章　测试脚本自身的修正（U6）

### 3.1 问题

`03_ui.mjs` 原 U6 断言：

```js
const feng = rows[0];
rec('U6 头部标签', '雷火丰', '归魂卦应为八宫第8卦', `第${feng.guaXu}卦`, '归魂标签与五世世位并存');
```

`rec(cat, input, expected, actual, note)` 的 `expected` 是**自然语言描述句**，`actual` 是 `第N卦`。两个字符串永远不可能相等 → **无论产品对错，这条断言恒失败**。

上轮它「失败」是碰巧撞上了真实缺陷；修复后它仍然「失败」，但已经不是产品问题。

### 3.2 处理

**没有放宽条件，而是把断言改成可判定形式，并把覆盖从 1 卦扩到 3 卦（更严）**：

```js
// 预期来源（不调用被测代码）：坎宫八序由变爻规则现场推出 …（同 §2.1 表）
// 古法口径（《增删卜易·归魂游魂章》）：归魂=各宫第八卦，游魂=第七卦。
const EXPECT = [
  { name: '雷火丰',   guaXu: 6, shi: 5, ying: 2, tags: [] },
  { name: '地火明夷', guaXu: 7, shi: 4, ying: 1, tags: ['游魂'] },
  { name: '地水师',   guaXu: 8, shi: 3, ying: 6, tags: ['归魂'] },
];
for (let i = 0; i < EXPECT.length; i++) {
  const e = EXPECT[i], a = rows[i];
  const fmt = (o) => `${o.guaXu}卦/${o.shi}世${o.ying}应/${o.tags.join('·') || '无魂标签'}`;
  rec('U6 魂卦三态', e.name, fmt(e), fmt(a), `header=${a.header}`);
}
```

**同时修了 header 模板**：原模板 `${gong}宫：${name}（${tags.join('·')}）` 在无标签时会输出空括号 `坎宫：雷火丰（）`，与 `panview.js:53` 的真实逻辑（`gongTag.length ? ... : ''`）不一致。已照抄真实逻辑，现在输出 `坎宫：雷火丰`。

### 3.3 影响

- U6 用例数：1 → 3
- 三脚本总数：4541 → **4543**
- 预期值仍来自「八宫变爻规则 + 古法条文」，**不来自被测代码**
