# 06 · 候选修复方案比较

前提：本轮**只评估、不实施**。所有数字来自 `07_tomb-audit.mjs` 对 393,216 个场景的实算（`04`/`05`），反事实扣减只在内存中进行，生产代码未改一行。

## 一、事实基础（先看这四行，再看方案）

| 项 | 数值 | 来源 |
| --- | --- | --- |
| 场景总数 | 393,216（49,152 盘 × 8 域） | `05.scenarioSpace` |
| 195（用神入墓）触发 | 13,004 | `05.counts.t195` |
| 242（世爻入墓）触发 | 32,768 | `05.counts.t242` |
| 两条同时触发 | 4,660（**同爻 4,352**／不同爻 308） | `05.counts` |
| 同爻双触发中对象引用相同 | **4,352 / 4,352（100%）** | `05.catC_detail.sameObjectIdentity` |
| 同爻双触发中「旺相」占比 | 2,560 / 4,352 = **58.8%** | `05.catC_detail.byLingTai` |

结论：**需要讨论的重复只有 4,352 个场景**（C 类）。其余 8,344（仅 195）与 28,108（仅 242）分属不同爻，不是重复。

## 二、方案 A：同一爻、同一入墓事实只保留一个信号

**定义**：当 `用神持世`（`y === an.shi.occ`）且两条都触发时，抑制其中一条，只保留另一条。

| 变体 | 保留 | 抑制 | 古法依据 | 反事实影响 |
| --- | --- | --- | --- | --- |
| **A1（推荐方向）** | 195 用神入墓 | 242 世爻入墓 | 行 952「三墓即用爻入墓……非古法之世墓、身墓、命墓」；行 1330「自占看世爻，旺相者非真」→ 世墓成立条件远窄于实现 | 4,352 场景各 +1 分；档位变化 **1,311** 例 |
| A2 | 242 世爻入墓 | 195 用神入墓 | 无直接依据：行 952 恰好否定把世墓泛化 | 数值与 A1 **完全等价**（同为 -1），仅保留的文案不同 |

A1 的档位变化分布（4,352 个 C 类场景中）：

| 迁移 | 例数 | 按域 |
| --- | --- | --- |
| 凶 → 平 | 401 | career 101 / love 110 / wealth 102 / lost 88 |
| 大凶 → 凶 | 496 | career 233 / love 108 / wealth 93 / lost 62 |
| 平 → 吉 | 326 | career 172 / love 55 / wealth 66 / lost 33 |
| 吉 → 大吉 | 88 | career 59 / love 15 / wealth 10 / lost 4 |
| **合计档位变化** | **1,311** | career 565 / love 288 / wealth 271 / lost 187 |
| 档位不变（仅分数 +1） | 3,041 | — |

已知 6 例（戌月 love）在 A1 下的结果：`-1 凶 → 0 平`（不是回吉——①② 各扣的 1 分仍在，见 `03`）。

**判断条件（若日后实施）**：

```text
触发抑制 242 的完整条件：
  domainId ∉ {health, decision, life, people}   // 与 195 的域限制一致
  且 yongOccs.length > 0
  且 !ys.useYing                                 // 应爻为用时 195 不成立，无需抑制
  且 y === an.shi.occ                            // 对象同一，而非仅 pos 相同
  且 y.state.ruMu === true                       // 即两条都已触发
保留：195 全部照旧
不改：任何权重、阈值、其他规则
```

**误伤风险**：低。条件收得比「同 pos」更严（要求对象同一），且四个特殊域完全不碰。**已知风险**：A1 会让 4,352 个场景统一向吉侧移动 1 分，属系统性单向偏移，需在发布说明里写清。

## 三、方案 B：通过统一的入墓事实层去重

**定义**：在事实层为每个入墓事实生成标识 `factId = mu|{爻位}|{来源}`，规则消费事实时按 `factId` 去重。

**效果**：
- 对本轮 195/242 这对：效果**等同于 A1**（同一爻同一来源 → 同一 factId），无额外收益；
- 额外收益在 lost 域：`195 + lost:434` 读的是同一个 `y.state.ruMu`，全量 **2,656 例**；其中 `195 + 242 + lost:434` **三计并存 816 例**。方案 A 不动这一组，方案 B 可以一并收掉。

**代价**：
- 要改 `liuyao-core.js` 或 `verdict.js` 的事实生产层，改动面远大于 A（A 只是在 `verdict.js` 里加一个布尔闸门）；
- 「同一事实、不同语义」（事被困 vs 物被藏）是否应当合并，古法没有直接答案（`02` 第五节缺口 1），有误并风险；
- 当前 `ruMu` 是布尔，来源信息（月/日）已被 `||` 吃掉，要做 factId 必须先改 `state` 结构 → 触碰核心数据契约，波及全部规则与门禁。

**结论**：方向正确，但**不适合与本次去重修复同批**。建议作为独立架构立项，先做 `state` 加来源字段，再谈事实层去重。

## 四、方案 C：保留双计，但明确其独立含义

需要同时满足（任务书 8.6 的要求）：

| 要求 | 本轮核查结果 |
| --- | --- |
| 两条规则分别表达什么 | 195＝事被困（行 1547 阻滞义）；242＝人被困（行 1330 危困义）——**语义确实可分** |
| 为什么同一爻可以同时触发 | 可以（用神持世）——但触发不等于应各计分 |
| 为什么双计不是重复计算 | **未找到依据**。行 1330 给的是「自占看世爻、代占看用神」的单一视角；行 952 明确否定把世墓泛化 |
| 双计的古法依据是什么 | **无**（`02` 第五节缺口 1） |
| 为什么不会造成系统性偏差 | 会：4,352 个场景全部向凶侧偏 1 分，且 58.8% 的场景同时还因旺相拿 +2 |

**结论**：语义可分成立，**分值可分不成立**。方案 C 不推荐。

## 五、方案 D：暂不修改，继续收集证据

成立条件：古法资料不足，或程序结构无法清晰区分不同入墓事实。

本轮的实际情况是：
- 古法资料**部分充分**：195 有直接依据；242 的依据窄于实现；双计无依据；
- 但存在一个**前置未决问题**：土墓库到底是戌还是辰（`02` 第三节）。已知 6 例全部依赖「土墓戌」这一流派选择；若按《增删卜易》正文（土墓辰），6 例根本不成立，方案 A 对它们的调整也就无从谈起。
- 另外「旺相者非真」未实现，属于跨议题（旺相/月破），本轮明令不得混改。

**结论**：方案 D 是**本轮的合法落地选择**——不是因为问题不存在，而是因为「土墓流派」这一前置项未定案，此时改代码会把流派分歧固化进程序。

## 六、方案 E（跨议题，本轮仅登记不评估实施）：旺相/生扶占优时抑制入墓

依据：行 1330「旺相者非真」、行 935「论生不论墓」。

反事实：抑制「用神旺相时的 195」与「世爻旺相时的 242」，全量 **8,418 个场景档位变化**（凶→平 2,760、平→吉 2,424、大凶→凶 2,050、吉→大吉 813、凶→吉 371），影响 8 个域全部（life 1,312 / wealth 1,136 / career 1,136 / love 1,058 / decision 1,002 / lost 998 / people 926 / health 850）。

**这一条的影响是方案 A 的 6.4 倍**，且与「月破与旺相冲突」（丑月 mask2144）同源，必须与月破、旺相一起单独立项，**严禁并入本次去重修复**。

## 八、推荐结论

1. **程序层面：195 与 242 在同爻时构成确认重复**（对象同一性 4,352/4,352）。
2. **古法层面：没有任何原文支持「同一入墓事实扣两次」**；行 1330 的「自占看世爻、代占看用神」倾向单一视角；行 952 明确把三墓限定于用爻。
3. **推荐方案：A1（保留 195、抑制 242）**，条件严格到「对象同一」，只作用于 195 生效的 4 个域。
4. **但本轮不建议立即实施**，原因是前置问题未定：土墓库「戌 vs 辰」的流派选择直接决定 6 例是否成立（`02` 第三节），且「旺相者非真」未实现会让 A1 的效果与古法本意部分错位。
5. **建议的下一步顺序**：
   ① 先定「土墓库」流派口径（项目文档留痕，选定后不再反复）；
   ② 再决定是否实施 A1（预期影响 1,311 例档位变化，需同步更新回归基线）；
   ③ 「旺相/月破抑制入墓」（方案 E）与月破议题合并立项；
   ④ lost 域 `195 + 434` 双计（2,656 例）与方案 B 一起，作为第二批。
