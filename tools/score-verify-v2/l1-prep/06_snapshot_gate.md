# 06 · 快照回归门禁方案

**本轮只给方案，不改动 `tools/gates.sh`，不新增脚本到正式门禁。**

---

## 1. 要解决什么问题

`aipack-samples/` 是 AI 资料包样例，共 20 个文件（六爻 9 + 塔罗 9 + `index.html` + `README.md`）。它是**冻结快照**，但没有任何机制保证它和当前生成器一致。

本轮实际发生的后果：`aipack-samples/` 里 10 个文件长期带着「雷火丰…归魂」这个**已被 L0 判定为错的事实**，直到人工发现才更新。如果这些样例被喂给模型或作为参考资料，会传播错误。

同类风险会反复出现：任何对 `guaTable.ts` / `wangshuai.ts` / `verdict.js` / `aipack.js` 的改动，都会让快照静默过期。

---

## 2. 最小可行方案

### 2.1 一个脚本：`tools/aipack-snapshot-check.mjs`

**职责**：重跑生成器到临时目录 → 与 `aipack-samples/` 逐字节比对 → 独立核验关键事实 → 按结果退出。

**不做的事**：不写 `aipack-samples/`、不改任何生产文件、不联网。

### 2.2 四层检查

#### 第 1 层 · 文件集一致

```
期望：临时目录文件集 === aipack-samples/ 文件集（按相对路径）
断言：差集为空
失败信息：多出 X 个 / 缺失 Y 个，列出文件名
```

#### 第 2 层 · 内容逐字节一致

```
对每个文件做 sha256 比对
断言：全部 SAME
失败信息：列出 CHANGED 的文件名 + 行级 diff 摘要（只报前 3 处差异）
```

**为什么逐字节而不是语义比对**：语义比对需要写解析器，本身可能出错；逐字节最严格，且生成器是确定性的（本轮已验证：正式运行与试跑产物 `cmp -s` 全部 SAME）。

#### 第 3 层 · 关键魂卦标签（**独立断言，不复用生成器自检**）

这是本方案的核心。**不能依赖 `ai-pack-sample.mjs:208` 的自检**，因为它有误报（`includes('null')` 会命中说明文字）。

独立断言清单：

| # | 检查对象 | 断言 |
|---|---|---|
| K1 | `liuyao-quick.txt` / `-classic.txt` / `-research.txt` 三份 | 全文不含 `归魂`、`游魂`（雷火丰不标魂） |
| K2 | 同上三份 | 含 `雷火丰` 且其头部事实串为 `雷火丰（震上离下，坎宫水，世5应2）` |
| K3 | `liuyao-*.json` 三份 | `chart_data.benGua.name === '雷火丰'`、`isGuiHun === false`、`isYouHun === false`、`shiPosition === 5`、`yingPosition === 2` |
| K4 | `liuyao-*.json` 三份 | `chart_data` 三者**完全相等**（deep equal） |
| K5 | `index.html` | 六爻相关事实串唯一，无第二套矛盾说法 |

**K1 的关键细节**：不能简单 `grep -c 归魂 === 0`。地火明夷、地水师如果被加进样例集，它们的本卦行里**应当**有 `（游魂）` / `（归魂）`。所以断言应写成：

```
对每份 txt：
  for each 行 containing 卦名 + （...）:
    若卦名 === '雷火丰' → 标签集合必须为空
    若卦名 === '地火明夷' → 标签集合必须 === {'游魂'}
    若卦名 === '地水师' → 标签集合必须 === {'归魂'}
```

即：**按卦名断言，而不是按全文计数**。

#### 第 4 层 · 四格式交叉一致

```
对六爻三模式：
  txt 里出现的每个「卦名（上下卦，宫五行，世X应Y）」事实串
  json 里 chart_data 对应字段
  html 里内嵌 JSON
  index.html 里的事实串
  → 四者取出的同一卦事实必须完全一致
```

本轮已人工做过这项核验（唯一事实串 `雷火丰（震上离下，坎宫水，世5应2）`），脚本化即可。

### 2.3 退出码与输出

```
全部通过 → exit 0，输出一行：aipack-snapshot-check: OK (20 files, K1-K5 pass)
有失败   → exit 1，输出分层失败清单
```

## 3. 与门禁的关系

### 3.1 建议挂载位置

在 `tools/gates.sh` 的 12 步之后追加为**第 13 步**：

```
[13/13] AI 资料包快照一致性
        node tools/aipack-snapshot-check.mjs
```

**为什么放最后**：它依赖 vendor 产物（第 2 步已验证同步）和 `verdict.js`（第 5 步已重建 bundle），放最后能确保用的是本轮产物。

**为什么只加一步**：`score-regression.mjs`（393216 场景）耗时太长，`liuyao-core` vitest 当前有必然失败的断言，两者都不宜此时入门禁。快照检查是最小、最快、最独立的一步。

### 3.2 前置条件（按顺序）

| # | 前置 | 说明 |
|---|---|---|
| 1 | 修 `verdict.js` 六冲/六合名单（P1-1、P1-2） | 否则快照一更新就带上错误评分，门禁会把错误固化 |
| 2 | 修 `golden.test.ts:146` 过期断言（P1-3） | 与快照无关，但同属"测试落后于实现"，一起处理 |
| 3 | **决定自检误报怎么处理**（见下） | 否则生成器每次运行都报 2 项失败 |

### 3.3 关于生成器自检误报的处置选项

`tools/ai-pack-sample.mjs:208`：

```js
if (txt.includes('undefined') || txt.includes('null')) problems.push(...)
```

**选项 A（推荐）：收紧断言，只检查真实空值**

```js
// 只查渲染产物里不该出现的字面量
if (/\bundefined\b/.test(txt)) problems.push(...)
// 去掉对 'null' 的全文检查；改为检查 JSON 结构里是否有意外的 null
```

理由：`null` 在 JSON 里是合法值（`zhouyi_text: null` 表示底本无此条），说明文字里出现 "null" 也是合法的。全文 `includes('null')` 是**错误的检查方式**，不是"文案不该出现 null"。

**选项 B：把说明文字排除在检查范围外**

先剥离 `constraints` 段落，再检查。比 A 更绕，不推荐。

**选项 C：不改生成器，在快照检查脚本里忽略这 2 项**

治标不治本，且会让自检长期红着，失去警示作用。**不推荐。**

**本轮未实施任何选项**（限制条款：不修改生产代码 / 未获批准前不改门禁）。建议在下一轮以独立小改动处理。

## 4. 快照本身的加固建议

### 4.1 版本戳（建议）

当前 `aipack-samples/` **无版本标识**，无法判断它是哪一版代码生成的。

建议在 `README.md` 里加一段（由生成器自动写入，非人工维护）：

```
生成时间: 2026-10-27T...
appVersion: v123
ruleVersion: 1
vendor sha256: 2492900 bytes / <hash>
生成命令: node tools/ai-pack-sample.mjs
```

**好处**：快照过期时能立刻看出差多少版。

**注意**：加时间戳会让每次生成都产生 CHANGED，与"逐字节比对"冲突。折中方案：时间戳写入独立文件 `aipack-samples/.build-meta.json`，并把它排除在逐字节比对之外（只比对 20 个产物文件）。

### 4.2 appVersion 硬编码问题（已知，记录）

`tools/ai-pack-sample.mjs` 里 `appVersion: 'v123'` 是硬编码，而当前线上是 v121、工程基线 `0ed9e89`。快照里的 `appVersion` 字段与真实版本无关。

**建议**：从 `app/sw.js` 的 `CACHE_NAME`（如 `qintian-v121`）或 `package.json` 读取。属小改动，本轮不动。

### 4.3 样例集是否应加地火明夷 / 地水师

当前样例只排了雷火丰一个盘。魂卦三态中，游魂、归魂没有样例覆盖。

**建议**：加两个盘（地火明夷、地水师）到样例集，使 K2/K3 能同时验证三种魂卦状态。

**代价**：样例从 9 个六爻文件变成 15 个，快照体积增加约 60%。

**判断**：值得。因为"雷火丰不标归魂"这个修复的**对称面**（明夷该标游魂、师该标归魂）当前无样例保护，下次若有人误改 `isYouHun`，快照检查发现不了。

**本轮未实施**（属新增内容，不在"更新旧快照"范围内）。

## 6. 不纳入本方案的内容

| 项 | 理由 |
|---|---|
| 塔罗样例的独立事实核验 | 塔罗 9 个文件本轮零变化，且不在六爻事实层范围内 |
| `score-regression.mjs` 入门禁 | 393216 场景，耗时过长；应做 `--quick` 模式后单独决策 |
| `liuyao-core` vitest 入门禁 | 16 文件 1784 行，需先修完已知失败断言，且需评估总耗时 |
| 语义级 diff（而非逐字节） | 需写解析器，本身引入新风险 |
| 自动提交快照更新 | 违反"快照更新需人工确认"原则 |
