# 04 · L1 独立测试设计

## 0. 设计原则（最重要的一条）

**独立预期不得由被测代码生成。**

现有 `key-fact-audit/scripts/verify-facts.mjs` 已确立正确范式，本轮沿用并扩展：

| 被测对象 | 允许的独立预期来源 | 禁止的预期来源 |
|---|---|---|
| 八卦爻位 | 《易经》卦画定义人工固定 + 第三方 `getTrigramsFromValues` 反查 | 用 `getShouGuaPan` 自己的输出当预期 |
| 旬空 | 六十甲子独立推旬首 | 用 `pan.xunKong` 当预期 |
| 世应 | 京房八宫标准映射独立实现 | 用 `SHI_OF_XU` 当预期 |
| 月令五态 | 古法五态定义逐对枚举 | 用 `lingTaiOf` 当预期 |
| 六冲/六合卦 | 古法定义（初四/二五/三上两两相冲/相合）独立枚举 | 用 `LIU_CHONG_GUA` 当预期 |
| 五行生克 | 相生相克链通行定义 | 用 `relationOf` 当预期 |
| 长生十二宫 | 《增删卜易》火土同宫表 | 用 `CHANG_SHENG` 当预期 |

对 `verdict.js` 这类"规则应用层"，独立预期还必须**独立于评分权重**：先独立判定"这条规则该不该触发"，再看"触发了权重是几"。前者是事实，后者是工程取值。

## 1. 六冲卦名单（T2 扩展）

| 项 | 内容 |
|---|---|
| 输入条件 | 64 卦全枚举，每卦取内卦三爻、外卦三爻的阴阳 |
| 独立预期 | 古法定义：初爻与四爻、二爻与五爻、三爻与上爻，三对**全部相冲**即为六冲卦。阴阳相冲 = 两爻阴阳相反。独立枚举得 10 个：乾为天、坤为地、坎为水、离为火、震为雷、艮为山、巽为风、兑为泽、天雷无妄、雷天大壮 |
| 正例 | 天雷无妄（震下乾上）：初阳四阳同、二阴五阳异、三阴上阳异 —— 需按实际卦画核对；雷天大壮同理 |
| 反例 | 泽火革（离下兑上）：初阳四阳同 → 不构成六冲 |
| 边界 | 八纯卦六爻全同阴阳，初四、二五、三上三对全冲 → 全部是六冲卦（10 个里的前 8 个） |
| 规则来源 | 古法六冲卦定义；`constants.ts` 与独立核对均得 10 |
| 实现位置 | `app/js/verdict.js:35` `LIU_CHONG_GUA`（8 个）<br>`liuyao-core/src/constants.ts`（10 个，正确） |
| 测试位置 | 现有 `verify-facts.mjs` T2 已做独立/constants/verdict 三方比对；**缺的是把该比对接入门禁并断言 verdict 侧** |
| 风险等级 | **高**（确定错误，影响 love/people 两域评分） |

**断言形式**：

```
独立枚举集合 === constants 集合      // 已通过
verdict.LIU_CHONG_GUA === 独立枚举集合  // 当前 FAIL，缺 2 个
```

## 3. 回头生 / 回头克

| 项 | 内容 |
|---|---|
| 输入条件 | 任取动爻，给定本位地支 `zhi` 与变爻地支 `bianZhi`，覆盖五行全部 25 种组合 |
| 独立预期 | 独立实现：查 `ZHI_WUXING` 得两爻五行 → 用相生相克链判定。变爻五行生本位五行 → 回头生；变爻五行克本位五行 → 回头克；其余不算。**不调用 `relationOf`**（因 `relationOf` 本身是被测对象） |
| 正例 | 初爻子水动化未土：未土克子水 → 回头克（`najia-analysis.test.ts` 已有此例，水雷屯） |
| 反例 | 上爻子水动化卯木：水生木（本位生变爻），非回头生也非回头克 —— 古法叫"化泄"，当前不标记 |
| 边界 | ① 变爻与本位同五行（比和）：既非生也非克 ② 变爻地支 == 本位地支（伏吟）时回头生克均不成立 ③ 变爻地支冲本位（反吟）与回头克可能同时成立，需明确二者是并列还是互斥 |
| 规则来源 | 《增删卜易·动变章》「变出之爻生我、比和者吉，克我、化退化墓者凶」 |
| 实现位置 | `wangshuai.ts:129-137` |
| 测试位置 | `najia-analysis.test.ts` 2 例（覆盖 1 正 1 反）；**缺 25 组全枚举** |
| 风险等级 | 中（核心事实，当前仅 2 例支撑） |

**补充边界用例**：伏吟 + 回头克是否可并存（若 `bianZhi === zhi` 则 `relationOf` 必为"同"，故不可能，但应有显式断言固化该结论）。

## 8. 用神选取

| 项 | 内容 |
|---|---|
| 输入条件 | 8 个问事域 × 64 卦 × 2 性别 = 1024 组 |
| 独立预期 | 独立硬编码《增删卜易·取用章》取用表：财运→妻财；事业→官鬼、父母；感情→男取妻财、女取官鬼；疾病→官鬼、子孙；考试→父母、官鬼；合作→应爻、兄弟；行人→应爻；失物→妻财；其他→应爻。**不从 `DOMAIN_YONGSHEN` 取** |
| 正例 | 男占感情 → 妻财；女占感情 → 官鬼（`najia-analysis.test.ts` 已有此例） |
| 反例 | 男占感情取官鬼 → 错 |
| 边界 | ① 用神多现（T6：1952 组平票，同六亲 1120、跨六亲 832）② 用神不上卦但有伏神 ③ 用神既不上卦也无伏神 |
| 规则来源 | 《增删卜易·取用章》《增删卜易·用神章》 |
| 实现位置 | `najiaAnalysis.ts:122-132` `DOMAIN_YONGSHEN`；`verdict.js` 的 `rank()` 多现取用 |
| 测试位置 | `najia-analysis.test.ts` 3 例（财运/感情/合作）；**缺多现平票的独立裁决验证** |
| 风险等级 | **高**（多现取用规则直接影响断语；T6 平票 1952 组意味着取用策略有大量实际影响） |

**多现取用的独立预期**（古法「舍其闲爻而用持世、舍其安静而用发动、舍其月破而用不破、舍其旬空而用不空」）：

独立实现一个排序器，优先级：持世 > 发动 > 不空不破 > 月日合，平票取最上爻。再与 `verdict.js` 的 `rank()` 比对。注意：这是"用古法文字独立实现"，仍不是"用古籍原文当预期"，因为古法本身没给权重数值——该点必须在测试注释中写明这是**口径固化**而非**事实核对**。

## 9. 入墓双计（评分结构断言）

| 项 | 内容 |
|---|---|
| 输入条件 | 构造"用神持世 + 世爻入墓"的盘（如戌月、火爻持世） |
| 独立预期 | 入墓是**一个**事实，应只扣一次。当前扣两次（用神侧 -1 + 世爻侧 -1）→ 断言 `signals` 中"入墓"类信号计数 === 1 |
| 正例 | 用神不持世、二者分别入墓 → 计 2 次（不同爻，不同事实） |
| 反例 | 用神持世、同一爻入墓 → 计 2 次（同一事实重复） |
| 边界 | health 域走专项块，不适用 |
| 规则来源 | 去重原则（同一基础因素不重复计分），非古籍原文 |
| 实现位置 | `verdict.js` 三、世爻自身 `if (st.ruMu) add(-1, ...)` |
| 测试位置 | 无 |
| 风险等级 | 中（MEMORY 记录 6 例实际反转） |
