# 候选规则差异表（v2 · 逐条、可判定）

实验：12 月令 × 4096 爻型 × 8 问事域 = 393,216 条，零非法盘。生产引擎 `app/js/verdict.js` 全程只读，
所有"候选规则"在 `tools/score-verify-v2/scripts/` 内离线实现，不改任何 app/ 文件。
档位编码：2=大吉(≥4)，1=吉(≥1)，0=平，-1=凶(≤-1)，-2=大凶(≤-4)。

## 修正① 用神持世时，用神月建旺衰 与 世爻月建旺衰 重复

| 项 | 内容 |
|---|---|
| 原规则 | line190 用神得月令之气 +2（`yongwang`）；line191/192 用神休/囚死于月 -1（`yongxiu/yongshuai`）；**同时** line235 世爻旺/相于月 +1（`shiwang`）；line236 世爻囚死于月 -1（`shishuai`） |
| 候选规则 | **当且仅当**「引擎选中的用神爻就是世爻」时，同一事实只计一次：保留用神侧（+2/-1，主体规则），世爻侧（line235/236，+1/-1）置 0。用神不持世时两条各自独立，完全不动 |
| 具体判定条件 | `选中用神.pos === 世爻.pos`（复刻 verdict rank：持世8/发动4/不空破2/月日合1，平票取首爻）。取应爻为用（useYing）时不触发 |
| 古法依据 | 《增删卜易·用神章》要旨：自占世爻即用神，"不曰世爻而曰用神"——同一爻的月令旺衰是一个基础因素，不应因"用神""世爻"两个名字加两次。**仅当同爻才成立**，故条件化 |
| 影响面 | 分数变 42,240 条；档位变 11,217 条；跨大吉↔吉、平↔凶、大凶↔凶；**0 例吉凶反转**（不跨正负）。仅 career/wealth/love/lost 四域；分域档位变 career3775/wealth2453/love2736/lost2253；health/decision/life/people=0 |
| 风险 | 低。只在同爻时去重；rank 平票取数组首爻的既有不确定性（遗留#5）会影响"是否持世"判定，需与取用显式化一并锁定 |

## 修正② 世应相冲/相合 与 六冲卦/六合卦 的条件性重复（占婚 love）

| 项 | 内容 |
|---|---|
| 原规则 | line264 世应相合 +1（`shiyinghe`）；line267 世应相冲 love 域 -2（`shiyingchong`）；**同时** line310 本卦六冲卦 -1（`liuchonggua`）、line311 本卦六合卦 +1（`liuhegua`） |
| 候选规则 | love 域，**当卦象冲/合与世应冲/合在同一盘真共现时**，只计世应这条（冲保留 -2、合保留 +1，是占婚主体），卦象那条置 0。不共现就各计各的 |
| 具体判定条件 | 冲侧：同盘信号同时含 `shiyingchong` 与 `liuchonggua`（八纯卦世应 8/8 固定相冲，512 爻型结构上必然共现）。合侧：同盘同时含 `shiyinghe` 与 `liuhegua`——**必须真共现**，六合卦 8 个里只有 5 个世应相合；火地晋、山雷颐、地泽临 3 个例外的世应既不合也不冲，其 `liuhegua` +1 独立保留 |
| 古法依据 | 《增删卜易·婚姻章》以世应与卦体论婚；当卦体即六冲、世应又正冲时，"易散"是同一事实的两种表述，叠扣属重复；但六合卦不必然世应合（有三例外），故不能无脑并——这正是"不因同名就并、不因异名就独立"的落地 |
| 影响面 | 分数变 9,984 条；档位变 2,519 条（全在 love）；**0 例吉凶反转**。被切频次 liuchonggua 6144 / liuhegua 3840 |
| 风险 | 低。合侧已按真共现严格条件化，三例外零误并（特殊场景报告 liuheExcept 命中 2304、错误归并 0）。line313/314 六冲变六合(+2)/六合变六冲(-2) 是"事态走向"的独立规则，**本轮完全不并入、不改动** |

## 修正③ 用神持世时，用神回头生/克 与 世爻回头生/克 重复

| 项 | 内容 |
|---|---|
| 原规则 | line202 用神回头克 -2（`yonghuike`；行人域 line389 同义）；line201 用神回头生 +2（`yonghuisheng`）；**同时** line237 世爻回头克 -2（`shihuike`）；line238 世爻回头生 +1（`shihuisheng`） |
| 候选规则 | **当且仅当**「选中用神就是发动的世爻、且该爻化回头克/生」时，克保留用神侧 -2、剔世爻侧 -2；生保留用神侧 +2、剔世爻侧 +1。用神不持世、或用神与世是不同动爻时，两侧是两个独立动变，**一律各自保留**。health 域不走此规则（见修正④，且世爻在 health 有独立的"病人"语义） |
| 具体判定条件 | `选中用神.pos===世爻.pos && 该爻.moving && state.huaTouKe/huaTouSheng && domain!=='health'`。验证：用神不持世但用神、世爻各有回头克/生的盘共 5,706 个，全部独立保留、零误并 |
| 古法依据 | 《增删卜易·动变章》：变爻只回头作用于生它的本位动爻，"并不能生克他爻"。自占世爻即用神，故同一根动爻化回头克只数一次（克 -2 记一次，不是 -4）。**不同爻各自化克是两件事**，故条件化。另：现行克(-2/-2)与生(+2/+1)权重不对称，无古籍依据，列入权重设计类，本轮不改 |
| 影响面 | 分数变 11,040 条；档位变 3,581 条；**吉凶反转 294 例（全部凶→吉，无一例吉→凶）**；分域 career1236/love833/wealth853/lost659。反转例方向合理：原算法把同一回头克扣两遍压成凶，去重后回到中性/吉 |
| 风险 | 中（因出现吉凶档位反转）。反转方向单一且可逐例解释，但"回头克是否足以单条定凶"本身有流派分歧，建议主人先抽验反转例（数据见 `v2-reverse-cases.json`）再决定是否上线 |

## 修正④ health 域：通用回头生/克 与 疾病专项回头生/克 同因双计（v2 新发现）

| 项 | 内容 |
|---|---|
| 原规则 | health 域下，世爻发动化回头克时：line237 通用块 `世爻动化回头克——自己的动作反伤自己` **-2**，与 line327 专项块 `世爻动化回头克、或化官鬼——自占病最险，速治` **-2**，对同一 `an.shi.occ.state.huaTouKe` 各触发一次（合计 -4）。回头生同理：line238 +1 与 line328 `得生得救` +1（合计 +2） |
| 候选规则 | health 域下同一世爻同一动变只计专项古法条（克保留 line327 的 -2，剔通用 line237 的 -2；生保留 line328 +1，剔通用 line238 +1）。实现上等价于"health 分支与通用分支对该信号二选一（else）"，不是删功能 |
| 具体判定条件 | `domain==='health' && 世爻.moving && state.huaTouKe`（生同构）。与修正③互斥：health 不走"用神=官鬼 vs 世爻"的归并，避免把"病(官鬼)克病人(世)"误当同一因素 |
| 古法依据 | 《增删卜易·疾病章》《动变章》：自占病世为病人，世动化回头克是一个凶象，疾病章只是换了占病语境重申，并非第二个独立克。属同一输入、同一基础因素、同一计分目的 |
| 影响面 | 分数变 10,848 条；档位变 4,639 条（**全部在 health**）；吉凶反转 335 例（全部凶→吉）。是本轮档位/反转最集中的单项 |
| 风险 | 中。health 结论敏感；且该域另有"官鬼安静或空破"文案矛盾（遗留#4）与"世爻旬空 -1 / 近病逢空 +1"同盘正负并存（属冲突非重复，需专业判断，不在本轮）。建议 health 域单独评审后再上 |

## 权重折减（仅敏感性实验，不作为候选规则）

| 项 | 内容 |
|---|---|
| 做法 | 上述 4 组的"副信号"不置 0，而 ×0.5（k=0.5），其余同 vall |
| 结果 | 分数变 58,640（与 vall 同），档位变 11,817（vall 为 18,686），吉凶反转 **0**（vall 为 510） |
| 定位 | 证明"折减比硬并温和、能消掉全部跨正负反转"，但 **k=0.5 没有任何古籍依据**，仅展示结果对处理方式的敏感度，不得作为古法规则写进引擎，也不得对外宣称其更准 |
