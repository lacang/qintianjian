# 提交A 补充说明：①② 单项各 0 反转，但组合后出现 71 例「吉→凶」

## 一、必须更正的一处表述
此前材料写「①② 实验数据没有吉凶反转」，该结论只对**单项**成立：
- 仅 ①（世爻月建旺衰去重）：反转 0
- 仅 ②（爱情域世应冲合去重）：反转 0
- **①② 组合（= 提交A 实际形态）：71 例吉→凶**

71 例全部为 love 域、全部 1 → -1（Δ = -2）。清单：`reversals-v12-full.json` / `.csv`，
逐条复算明细：`analyzed-v12-71.csv`，**71 / 71 与程序复算一致**。

## 二、机制：两条独立去重叠加，各去 1 分
样例：辰月 mask72 雷地豫之天火同人（love）

```
原算法信号（legacy 引擎，完整 6 条）
 +2  妻财（乙未，初爻、持世）得月令之气（旺于月）        ← 用神侧，保留
 -2  妻财（乙未，初爻、持世）发动却被变爻回头克          ← 用神侧，保留
 -2  世爻动化回头克                                    ← ③ 处理（提交A 未启用，故仍在计分）
 +1  世爻旺于月，你自己有底气、扛得住事                  ← ① 抑制（用神侧 +2 已覆盖同一月令）
 +1  世应相合——你和对方合得来、彼此接受                  ← 保留
 +1  本卦是六合卦，占婚最宜，主易合、关系黏得住           ← ② 抑制（世应相合 +1 已覆盖同一合象）
= +2 -2 -2 +1 +1 +1 = 1（吉）
```

> **勘误（2026-10-27 复核后补）**：本节初版只摘录了 5 条信号，漏掉第 3 条「世爻动化回头克 −2」，
> 导致按摘录求和得 +3、与「+1→−1」不符。该信号在提交A（①②）阶段**仍然生效**（③ 只在提交B 才启用），
> 补上后原始分 = +1、修复后 = −1，与程序实算完全一致。完整账目见 `71-reversal-audit-report.md` 第四节。
> 此为文档摘录不完整，**不是程序错误**。

- ① 去掉 +1（世爻旺）→ 0（平）
- ② 去掉 +1（六合卦）→ -1（凶）
- 两条都成立，因为它们是**两个不同基础因素**（月令旺衰、世应合象），各自被两条规则重复计了一次。
  分别去重后各减 1，叠加起来减 2，跨过了「吉→凶」的档位阈值。

## 三、判断
- 这不是误抑制：被去掉的两条都是与保留项同源同事实的重复项（月令 / 合象各只剩一次）。
- 也不是「①② 有 bug」：单项各减 1 时都在阈值内，组合后减 2 才越界，属阈值效应。
- 但**结果上确实出现了吉→凶**，必须让审核方知情，不能以「单项 0 反转」代表组合 0 反转。
- 71 例全部落在 love 域，因为 ② 只作用于爱情域；这也意味着爱情域是本轮风险最集中的域。

## 四、可选处置（待裁决，本轮不擅自改）
1. 接受现状：去重正确优先，档位变化是正确去重的自然结果（推荐，与 mask322 定平同一逻辑）。
2. 阈值复核：love 域阈值是否过窄（1 分即吉、-1 即凶），属独立议题，不在本轮范围。
3. 分档过渡：不采用，会引入新的权重设计，缺古籍依据。
