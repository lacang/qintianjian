【一、97,492 的统计单位与去重口径（P0 第三项）】

统计单位
  一条记录 = 一个 (mask, 月令, 日辰, 域) 四元组的判读结果。
  空间 = 4096 mask × 12 月令 × 12 日辰 × 8 域 = 4,718,592。

  月令取 12 地支（子丑寅卯辰巳午未申酉戌亥），日辰同样取 12 地支，
  日干由 (月支序 + 日支序) % 10 推出，保证干支组合合法。

计入条件
  levelDiff 的定义是 levelPre !== levelPost，
  level 由 score 分段得出：>=4→2 / >=1→1 / <=-4→-2 / <=-1→-1 / 其余→0。
  所以 97,492 是「档位发生变化的记录数」，不含仅分数变化的记录。

去重
  四元组天然唯一，无重复计数。一条记录只归入一个 byClass 类别。

分类互斥性
  byClass 各类之和 = 97,492，无遗漏无重叠（已核）：
  L 17,040 + X 9,552 + L+R 133 + R 2,913 + P 66,390
  + L+P 377 + XA 452 + P+XA 64 + P+R 571 = 97,492 ✓

占比
  97,492 / 4,718,592 = 2.066%
  即 97.93% 的判读结果档位不变。

统计粒度说明（这是需要董事长注意的一点）
  同一个 mask 在不同月令/日辰下是不同记录，会分别计数。
  一个物理盘在 144 种月日组合下可能多次被计入。
  因此 97,492 是「判读次数」而非「独立用户场景数」。
  双口径表述（董事长 2026-10-29 核定，对外统一使用）：
    全量穷举共覆盖 4,718,592 次判读，发现 97,492 次吉凶档位变化，
    占判读次数的约 2.07%。这些记录来自 4096 种六爻组合、12 种月令、
    12 种日辰及 8 个问事域。若仅按 144 个月日组合折算，约相当于
    677 个卦象—问事域组合，但这只是统计规模的换算，
    不代表 677 个真实用户或实际咨询场景。

  三条禁止（避免误读）：
    · 97,492 是判读记录数，不是用户数，也不是独立真实卦例数。
    · 约 677 是折算值，不得直接宣称是「677 个独立盘」而不附加定义。
    · 同一卦象在不同问事域属于不同判读记录；即便除以 144，
      也不能把折算结果等同于真实用户场景。


【二、董事长问：日破与暗动是否所有条件下互斥】

是，严格互斥，且是结构性保证而非经验观察。

POST 代码（app/js/wangshuai.ts）
  lingTaiEff = (yuePo && lingTai === '旺') ? '休' : lingTai
  anDong     = riChong && (lingTaiEff === '旺' || lingTaiEff === '相')
  riPo       = riChong && !(lingTaiEff === '旺' || lingTaiEff === '相')

  两者是同一个 riChong 前提下对 lingTaiEff 的正反判断，
  不存在第三种分支，结构上不可能同时为真。

PRE 代码（V0 vendor）
  anDong = riChong && (lingTai === '旺' || lingTai === '相')
  riPo   = riChong && (lingTai === '死' || lingTai === '囚')

  PRE 存在第三个状态：riChong && lingTai === '休' 时两者皆 false。
  这是本次改动的核心——「日冲休态」在 v121 里是待定，在 v122 里归日破。

实测验证
  检查范围：4,718,592 判读 × 6 爻 × PRE/POST 两侧
  期望检查次数：56,623,104
  实际 anDong && riPo 同时为真：0 次
  PRE 侧：0  POST 侧：0

  这是全枚举而非抽样，因此「所有条件下互斥」可以直接成立。


【三、董事长问：riPo 新增与 anDong 移除是否严格对应同一批爻】

不是同一批。anDong 移除是 riPo 新增的真子集。

爻级数据（evidence/yao-ridiff-matrix.json）
  riPo 新增                 32,768 爻
    其中 PRE anDong = true    4,096 爻   ← 这 4,096 条才是 anDong 的替换
    其中 PRE anDong = false  28,672 爻   ← 这是「休态待定」的新增覆盖
  anDong 移除                4,096 爻，全部 POST riPo = true
  riPo 移除                      0 爻
  anDong 新增                    0 爻

对应关系
  anDong 移除 4,096 ⊂ riPo 新增 32,768，一一对应，方向是「暗动变日破」。
  其余 28,672 爻不是替换，是 v121 里根本没有判定结果的状态
  （日冲 + 休态 → 既不暗动也不日破，属于未定义），v122 补上了判定。

  这 28,672 爻占 riPo 新增的 87.5%，是本次改动的主体，
  也是「休态静爻被日冲归日破」这条批复的实际作用面。

状态转移证据
  休|false|true|false|false → 休|false|true|false|true   28,672
    （PRE：日冲但休态，anDong/riPo 皆 false → POST：riPo = true）
  旺|true|true|true|false   → 休|true|true|false|true     4,096
    （PRE：旺+月破+日冲，anDong=true → POST：月破压旺为休，anDong 消失、riPo 成立）


【四、董事长问：日破是否通过用神选择/旺衰汇总间接改评分】

不通过用神选择，只通过通用用神本体加减，且被 skipYongBody 限制在 4 个域。

用神选择不受影响
  用神选择逻辑（六亲取用、应爻取用）只读 domainId、question、
  世应关系与六亲映射，不读 anDong / riPo 状态。
  riPo 是旺衰层的输出，不是用神选择的输入。
  方向是单向的：用神选定 → 判断该用神爻的旺衰 → 输出 riPo。
  不存在「riPo 反过来改用神」的路径。

评分路径唯一
  riPo 进入评分的唯一入口是 verdict.js 第 210-211 行的通用用神本体加减，
  且该段被 skipYongBody 门控：
    const skipYongBody = new Set(['health','decision','life','people']);
    if (y && !skipYongBody.has(domainId)) { ... anDong +1 / riPo -1 ... }

  所以 riPo 只影响 career / wealth / love / lost 四个域。

实测印证（这是最有力的证据）
  ribo 通道记录按域分布：
    career 3,344    wealth 3,216    love 3,216    lost 3,216
    health 0        decision 0      life 0        people 0
  andong 通道按域分布：
    wealth 368      love 368        lost 368      career 224
    health 0        decision 0      life 0        people 0

  四个被 skipYongBody 排除的域，日破/暗动变化严格为 0。
  代码约束与实际行为完全一致，没有旁路。

  补充：people 域另有独立证据——people 专项块 10 条 add() 调用
  （verdict.js:403-425）全部只依赖 anDong / huaTui / huaJin / ruMu /
  fengJue / xunKong / yuePo / huaTouKe / 世应五行 / 世爻旬空 / 六冲卦，
  没有任何一条读 y.state.riPo。
  所以即使 skipYongBody 不存在，日破对行人域也不会产生信号。


【五、董事长问：2,913 与 571 的分类关系、有无重复计数】

分类关系
  full-enum-144.json byClass 中与日破相关的三项：
    R     2,913  只有日破/暗动通道变化
    P+R     571  月破类（wangxiang/shituo/chishi）与日破同时变化
    L+R     133  六合名单与日破同时变化
    ─────────────
    合计  3,617

  本次独立复核（report-ribo.mjs，档位变化口径）：
    ribo 通道档位变化 = 3,617 ✓ 完全一致

  拆分验证：
    3,617 − 571 − 133 = 2,913 ✓

571 不是巧合，是必然
  andong 档位变化实测 = 571，与 full-enum 的 P+R 571 相等。
  原因：anDong 移除的 4,096 爻全部来自「旺 + 月破」→「休」的转变，
  这个转变本身就会改变 wangxiang（月破）信号的内容与权重。
  所以 andong 变化必然同时是 P 变化。
  因此「有 andong 变化且有 ribo 变化」的记录数 = 「有 P 变化且有 R 变化」
  的记录数 = 571。两条路径算出同一个数，互为印证。

无重复计数
  byClass 每类互斥，一条记录只进一类。
  R / P+R / L+R 三项不重叠，相加正好等于 ribo 通道总档位变化数。

133 与 115 的差异（诚实标注）
  我的脚本用「liuhe 信号是否出现/消失」判定六合共现，得 115。
  full-enum 用 liuhunhun 的 ruleId delta 判定，得 133。差 18 条。
  两者口径不同，我未做精确对齐。报告采用 full-enum 的 133，
  但请注意这个数未经独立复核。如需精确值，需要按 liuhunhun 组
  的权重与文本变化重新判定后重跑。

【八、风险判断】

可以接受的部分：
  · 日破与暗动严格互斥，56.6M 次检查零反例
  · 评分路径唯一且受 skipYongBody 门控，实测四域零变化印证
  · 用神选择不受 riPo 影响，方向单向
  · 87.6% 的日破变化就是单条 -1，不产生连锁
  · 只占 97,492 的 3.7%，不是影响面主体

需要董事长注意的部分：
  ① 档位翻转（吉→凶）的精确条数（已从档位流转矩阵直接统计）：

     全量口径（重要澄清）：
    4,718,592 判读中，吉→凶跨正负翻转共 7,590 条（含所有通道）。
    其中由日破/暗动通道参与的 141 条，占全量翻转的 1.9%。
    其余 7,449 条由月破失气、六合名单、六冲名单等其他通道造成。
    董事长批示中的「141 条」指日破通道这部分，不是全量翻转数。

  ribo 通道 12,992 条中：
       吉→凶（levelPre>0 且 levelPost<0）      141 条
         1→-1   86    1→-2   45    2→-1   10
       吉→中（levelPre>0 且 levelPost=0）      400 条
         1→0   400

       结论：日破通道造成「吉→凶」跨正负翻转 141 条，

     如果董事长认为「吉凶翻转」比「同档内分数变化」严重得多，
     这 141 条应作为重点审查对象，我可以导出逐条明细。

  ② 97,492 的折算口径（已按董事长核定表述固定，见第一节）。

  ③ 133（六合共现）未经独立复核，口径与我的 115 不同。
     如果要引用，建议先对齐。
