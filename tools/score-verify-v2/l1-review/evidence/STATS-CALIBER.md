统计口径：**候选 v122 vs 本地 main**（即"本批 L1 到底改了什么"），全量 393216 判读。

| 桶 | 条数 | 定义（判读进入该桶的充要条件） |

| `chong_gua` | 2270 | 六冲名单变化，且无旺衰类变化。信号层体现为 love 域 `liuhunhun` 增删，或 people 域 `xingren`（行人六冲，无去重闸门）增删 |

**互斥性**：归因代码是一条 `if / else if` 链，每个判读键只写入一个桶，不存在重复计数；`other=0` 且 `only=0` 说明 100% 归因、无遗漏无重叠。因此 **18758 = 2270 + 2632 + 12266 + 1404 + 186**，五桶相加即为总数，可直接验算。

**all_mixed 的定性（回答董事长第二问）**：它是**独立类别，不是额外共现标签**。定义上它只收"名单 + 旺衰同时变化"的判读，这些判读**已被排除**在前四桶之外（前四桶各自要求"无另一类变化"）。所以它既不能与前四类相加，也不是给前四类打的标签——它是互斥划分中的第五格。

## 三、18758 与 5088 的关系

### 3.1 两个数字是两个正交口径

| 口径 | 数字 | 比什么 | 变没变 |
|---|---|---|---|
| **全改动口径** | 18758 | 候选 v122 vs 本地 main（跨 vendor + 跨名单） | 信号构成**或**分数/档位任一变化 |
| **名单单维度口径** | 5088 | 同一 vendor 下，旧名单 vs 新名单 | 只比分数/档位 |

5088 之所以出现，是因为 `score-regression` 用同一份 vendor 重算 legacy 名单的应得分（`want`），再与当前 verdict 实得分（`got`）比——**失气在两侧同源，不产生差异**，剩下的差异只能来自名单。这是"名单修正单独影响多少判读"的独立测量。

### 3.2 两处 5088 为什么数值相同（不是巧合，是必然）

- 快照口径下，**名单相关的判读总数** = `chong_gua 2270 + he_gua 2632 + all_mixed 186` = **5088**。
- 名单信号是否触发只取决于「卦名是否在新旧名单中」；已实测 V0 vendor 与 cur vendor 在 4096 个 mask 下**卦名、世应 0 差异**，所以这批判读集合与 vendor 无关。
- 因此"名单相关判读集合"= 5088，而"纯名单口径下有分变化的判读数"也必然是这 5088 条（在纯名单口径里，L1 不参与抵消）。

三处独立复算均为 5088：
1. `score-regression` 的 legacy-vs-current mismatch = 5088；
2. 矩阵 `v2+v0 → cur+v0`（旧名单→新名单，vendor 固定 V0）= 5088；
3. 矩阵 `v2+cur → cur+cur`（旧名单→新名单，vendor 固定 cur）= 5088。

### 3.3 5074 与 14：为什么快照里"少"了 14 条

快照口径下卦象类 5088 条中，有分/档变化的只有 **5074** 条，另 **14** 条净分不变（仅信号构成变化）。

原因：这 14 条同时命中名单与失气，两者方向相反、数值抵消（例如名单 −1 与失气 +2 之外的组合使净差为 0）。在**纯名单口径**里失气不参与，抵消消失，这 14 条重新表现为分数变化，于是回到 5088 中。

对账恒等式：

```
5088（名单相关判读总数）
 = 5074（快照口径下有分变化） + 14（被失气反向抵消）
5088（纯名单口径下有分变化） = 5074 + 14
```

同理，全量口径的两个数字也对得上：

```
18758（信号或分数任一变化） = 18712（仅分数/档位变化） + 46（仅信号变化）
46 = 32（yuepo_wang 中仅信号） + 14（all_mixed 中仅信号）
```

矩阵脚本在完全不读快照的前提下独立复算出 **候选 vs 本地 main = 18712**，与 18758 − 46 完全一致。

## 四、各改动独立影响（矩阵口径：只比 score/level）

| 对比 | 差异条数 | 升档 | 降档 |
|---|---|---|---|
| L0 单独（legacy: v0→l0） | **0** | 0 | 0 |
| L1 单独（legacy: v0→l1） | 13824 | 0 | 6530 |
| L0+L1（无 V2） | 13824 | 0 | 6530 |
| 名单单独（vendor=v0） | 5088 | 297 | 1943 |
| V2 单独（vendor=v0） | 53744 | 8515 | 7015 |
| L0（叠加 V2） | **0** | 0 | 0 |
| L1（叠加 V2） | 13824 | 0 | 6131 |
| 名单（叠加 L1，vendor=cur） | 5088 | 294 | 1934 |
| V2（叠加 L0+L1） | 53488 | 8488 | 6279 |
| **候选 vs 本地 main** | **18712** | 290 | 8060 |
| **候选 vs 线上 v121** | **67416** | 8531 | 14538 |

**L0 = 0 的解释**：`verdict.js` 全文不出现 `isGuiHun` / `yinYang`（grep 0 命中），L0 修的是事实层标记与显示层（`panview.js` 归魂标签、`aipack.js` 游魂/归魂/八纯 flags、八纯首卦爻阴阳展示）。判读零影响是**预期且已实证**，L0 的正确性由 `golden.test.ts`（雷火丰 `isGuiHun=false`）与 aipack K1–K3 断言守护，不由判读差异证明。

**可加性检验**：
- L1(13824) + 名单(5088) = 18912，实际并集 18712 → 交集 200（= all_mixed 186 + 仅信号抵消 14）。
- V2(53744) + L1(13824) + 名单(5088) = 72656，实际候选 vs 线上 67416 → 交集 5240。

说明三类改动并非互不相干：同一判读可同时受两类影响。**因此不能用"单项影响之和"预估组合影响**，必须实测组合——这正是本矩阵存在的理由。

**V2 的 53744 为什么不进 18758**：V2 是 2026-10-27 并入本地 main 的独立批次，快照基线已包含它。把 V2 的影响算进本批，就是董事长警告的"把旧算法基线差异误报为新回归"。候选 vs 线上 v121 的 67416 才是"从线上一步跳到候选"的全貌，其中 V2 贡献约 53744、L1 贡献约 13824、名单贡献约 5088，重叠 5240。

## 五、需要董事长注意的风险数字

候选 vs 本地 main 有 **678 条跨过吉凶分界**（level 由正转负）：`1→-1` 644、`1→-2` 17、`2→-1` 17。

这是"月破失气"去掉不应给的 +2 旺相分后的直接结果，**属于预期变化，但预期不等于正确**。其正确性依据是 P0-2 的逐例证明（月破标记保留、−3 破分照计、非月破爻零影响、月破爻旺相加分归零），不是"数字符合预期"。
