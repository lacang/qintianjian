  统计口径：候选 v122 vs 本地 main（"本批到底改了什么"），全量 393,216 判读。

    chong_gua    2,270  六冲名单变化，无旺衰变化（love liuhunhun / people xingren）

  互斥性：归因代码是 if / else-if 链，每个判读键只写入一个桶，不存在重复计数。
  other = 0 且 only = 0，说明 100% 归因、无遗漏无重叠。因此

  前四桶各自要求"无另一类变化"，所以同时命中两类的判读已被排除在前四桶之外，
  只能落进 all_mixed。它既不能与前四类相加，也不是给前四类打的标签，而是
  互斥划分中的第五格。

  · 纯名单口径下失气不参与抵消，这 5,088 条必然全部有分变化

    ① score-regression 的 legacy-vs-current mismatch = 5,088

    ③ 矩阵 旧名单→新名单（vendor 固定 cur）= 5,088

4.4 5,074 与 14：快照里为什么"少"了 14 条

  快照口径下卦象类 5,088 条中，有分/档变化的只有 5,074 条，另 14 条净分不变
  （仅信号构成变化）——这 14 条同时命中名单与失气，方向相反、数值抵消。
  在纯名单口径里失气不参与，抵消消失，这 14 条重新表现为分数变化，回到 5,088。

    5,088（名单相关判读总数）= 5,074（快照口径有分变化）+ 14（被失气反向抵消）

  全量口径同理对账：
    18,758（信号或分数任一变化）= 18,712（仅分数/档位变化）+ 46（仅信号变化）
    46 = 32（yuepo_wang 中仅信号）+ 14（all_mixed 中仅信号）

  矩阵脚本在不读快照的前提下独立复算出"候选 vs 本地 main = 18,712"，
  与 18,758 − 46 完全一致。

7.1 L0 = 0 是预期，不是漏检

  verdict.js 全文不出现 isGuiHun / yinYang（grep 0 命中）。L0 修的是事实层标记
  与显示层（panview.js 归魂标签、aipack.js 游魂/归魂/八纯 flags、八纯首卦爻
  阴阳展示）。所以判读零影响是**预期且已实证**的结论。
  L0 的正确性由 golden.test.ts（雷火丰非归魂）与 aipack K1–K3 断言守护，
  不由判读差异证明——这一点必须说清，否则"0 差异"会被误读成"修复无效"。

7.2 不能把 V2 的影响算进本批

  V2 是 2026-10-27 并入本地 main 的独立批次，快照基线（本地 main）已包含它。
  把 V2 的 53,744 算进 18,758，就是董事长警告的"把旧算法基线差异误报为新回归"。
  "候选 vs 线上 v121 = 67,416"才是从线上一步跳到候选的全貌：
    V2 约 53,744 + L1 约 13,824 + 名单约 5,088，三者之和 72,656，
    实际并集 67,416 → 重叠 5,240 条（同一判读受多类影响）。
  同理 L1 + 名单：13,824 + 5,088 = 18,912，实际 18,712 → 交集 200
  （= all_mixed 186 + 仅信号抵消 14）。

  结论：三类改动并非互不相干，**不能用单项影响之和预估组合影响**，必须实测组合。
  这也是本矩阵存在的理由。
