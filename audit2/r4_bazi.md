### 3.2 但 `consistent` 字段是坏的（P0）

`wangShuaiEvidence` 里有一段"复刻旧卡公式"用于比对（bazi-extra.ts:1037-1046）：

后果链：
1. `baziview.js:144` 直接把这个字段渲染成红字提示：**「口径提示：断语卡判『偏弱』，本节按五行正理判『偏旺』，以本节为准（旧卡月令生克方向反，待修）」**，hover 的 tooltip 还再讲一遍"月令生我判成我生月令"

3. → **同一页自相矛盾，且把已修好的模块说成"待修"**。约四成用户会看到这条错误提示。

根因不是算法，是"对账对象"没跟着修复一起更新：`bazi-extra.ts:16-17` 与 `:1037-1038` 的注释至今仍写「verdicts.js 的 wxRel 在「生」的两支上方向反了」，这句已不成立。

`liuNian(bz, 2026)` 的参数是**立春年**，返回丙午；但它对 **2026-01-01 ~ 2026-02-03** 这段（八字仍属乙巳年）也返回丙午。当前 UI 用 `liChunYear()` 先算立春年再调，所以展示没错；但任何按公历年直接调用 `liuNian(bz, now.getFullYear())` 的地方，在每年头 34 天会错一年。`note` 已写"立春为界"，但函数签名/文档未标注参数含义。建议改名 `liChunYear` 形参或加断言。见 P3-2。

## 5. 时间层接入（bazi.ts）

### 5.1 三项必查

**① 不传地点是否真的走原路径** ✅

```
1990-06-15 08:00
无地点              → 庚午 壬午 辛亥 壬辰
显式 +8 / 关真太阳时 → 庚午 壬午 辛亥 壬辰   （一致）
```

`civilForPaipan` 在 `applied=false` 时返回原分量，`:148-150` 分支正确，向后兼容成立。

**② 真太阳时跨日后日/时柱是否正确** ✅

```
乌鲁木齐(87.6°E) 1994-08-01 00:30 → 甲戌 辛未 戊午 癸亥
北京 1994-07-31 22:20            → 甲戌 辛未 戊午 癸亥   （同日同时辰）
无地点 1994-08-01 00:30          → 甲戌 辛未 己未 甲子   （未折算）
```

日柱回退到 7-31（戊午）、时柱变亥时，与"按折算后钟面重排"完全一致 ✅。

**③ 有无双重扣减** ✅

- 夏令时：`1988-07-01 上海 09:30` → 时柱 **甲辰**（DST −1h → 08:30 → 真太阳 +6min → 辰时）；`无地点 09:30` → 乙巳；`solarToSiZhu 09:30` → **甲辰**。三者对齐，说明 DST 只扣一次，且与六爻口径同源 ✅
- 换日：`乌鲁木齐 01:30`（折算后 07-31 23:19）→ 己未日 甲子时，**只进一位**；`北京 23:50` → 庚申 丙子，与 `次日 00:05`（庚申 丙子）同日同时柱，晚子时不重复进位 ✅
- 立春 × 真太阳时：`2027-02-04 11:00 乌鲁木齐`（真太阳 ≈08:50）→ 丙午 辛丑，仍在立春前；`10:00 默认`→ 丁未 壬寅。年柱跟着**折算后**的时刻走，未出现两套时间混用 ✅

### 5.2 但**前端根本没把地点传进来**（P1）

| 调用点 | 传了什么 | 结果 |
|---|---|---|
| `app/js/baziview.js:34` `getBazi()` | 仅 year/month/day/hour/minute/gender | **city/place/lat/lon/utcOffsetHours/trueSolarTime 全部丢弃** |
| `app/js/hecanview.js:72` | 同上五项 | 同上 |
| `app/js/rhythmview.js:37` | year/month/day/hour/minute/**lat/lonEast**，**无 gender** | 时间层部分生效；大运方向错 |

`birthArgs()`（state.js:49-64）本来已经把 `...geo`（city/place/lat/lonEast/utcOffsetHours）和 `trueSolarTime` 都拼好了，**是视图自己重新拼了个只含五项的对象把它丢了**。

后果（可复现，用 vendor 包直接验）：

```
库层（app/vendor 包）调 paiBazi({...1988-07-01 09:30..., city:'上海'}) → 戊辰 戊午 丁巳 甲辰   （库里是对的）
而八字页实际调用（无 city）                                      → 戊辰 戊午 丁巳 乙巳   （时柱差一小时）
```

即：**1986–1991 夏令时出生者、以及所有需要真太阳时校正的出生时刻，八字页拿到的都是未校正的钟面时间**；而同一份输入在六爻页走 `solarToSiZhu` 是校正过的 → **同一个人，两个盘口径不同**。

### 5.3 rhythmview 不传 gender（P1）

```
1990-06-15 08:00 男（阳年男 → 应顺行）
有 gender：大运顺行，首步 癸未
无 gender：大运逆行，首步 辛巳   ← rhythmview 的处境
```

`paiBazi` 里 `genderCode = gender === '男' ? 1 : 0`（bazi.ts:184），`undefined` 静默当"女"。节奏图展示的大运序列对**阳年男/阴年女**整段反向。同一份 `birth` 对象里其实有 `gender`，只是没传。

### 5.4 两个次生问题

- `baziview` 的 `cacheKey`（:32）只含 年月日时分+性别+晚子时流派，**不含 city/geo**。将来补传地点后，用户切换出生地这一页不会重算。
- 八字页**没有任何"真太阳时/夏令时已校正"的提示行**（星盘 `astroview.js:130-145` 有）。若将来补传地点，用户会看到"出生 11:45"却排出 11:30 的四柱而无解释。
