## 1【P0】旺衰自证误报 41.94% → 0

**根因**：`bazi-extra.ts` 的 `consistent` 探针复刻的是 `verdicts.js` **修复前**的公式——把「月令生我」当 −1（我生月令）、把「日主生日支」当生扶。verdicts.js 已改成 `relMonth === 'sheng' → +2`、`beiSheng → −1`、`relDay === 'same' || 'sheng' → +1`，探针没跟着改，于是卡片判对、探针判错 → 页面弹红字。

**改法**（`bazi-extra.ts` 约 1036–1046 行）：`legacySheng` 两支方向归正（生我 +2 / 我生 −1），`legacyDayGood` 改为「日支同气 **或** 日支生我」；注释从「verdicts.js 方向反了」改为「漂移探针，两处公式必须同型」。`WangShuaiEvidence` 的字段注释同步（`consistent` = 公式漂移探针，不是流派比对）。

**实测（同一 1488 盘样本）**：

| | 修前 | 修后 |
|---|---|---|
| `consistent=false`（页面弹红字） | **624 / 1488 = 41.94%** | **0** |
| 其中「生我」月令 | 306 / 306 全误报 | 0 |
| 其中「我生(泄)」月令 | 318 / 318 全误报 | 0 |
| 「同我 / 我克 / 克我」 | 0 | 0 |
| 本节结论 vs 断语卡结论 | 1488/1488 本来就一致 | 1488/1488 一致 |

即：误报 100% 落在「月令生我 / 我生月令」两类，与审计判断一致；修后归零，且「本节结论 == 卡片结论」始终是 1488/1488 —— 说明**卡片是对的，错的是探针**。

## 3【P1】八字视图丢地点：时柱 乙巳 → 甲辰（与六爻一致）

**根因**：`baziview.js getBazi()` 只把 `year/month/day/hour/minute/gender` 传给 `paiBaziZi`，`birthArgs()` 已备好的 `city/place/lat/lonEast/utcOffsetHours/trueSolarTime` 全丢 → 内核 `civilForPaipan` 判定「无时区线索」，既不做夏令时还原也不做真太阳时。`hecanview.js computeNatal()` 同一处错误。

**改法**：两处都改成 `paiBaziZi({ ...a, lat: a.lat ?? a.latitude, lonEast: a.lonEast ?? a.longitude })`；`baziview` 的缓存键加上 `city/lat/lonEast/utcOffsetHours/trueSolarTime`（原来只到分钟+性别，改出生地不会失效 → 会复用旧盘）。

**实测 1988-07-01 09:30 沈阳**（1988 年 4/17–9/11 有夏令时）：

```
内核 resolveTime：civil 09:30 → 标准时 08:30（夏令时 −60min）→ 真太阳时 08:39（经度 +13.6 / 均时差 −3.75）
修前（只传年月日时）：八字时柱 乙巳      修后（透传地点）：甲辰
六爻盘（solarToSiZhu 同一 civil 输入）：甲辰  → 两盘一致
```

真实浏览器复跑（清 SW 后页面内实调）：`baziTime=甲辰`、`liuyaoTime=甲辰`，页面四柱区文本含「甲辰」，旺衰区无红字。

## 4【P1】rhythmview 丢 gender：大运 逆行 → 顺行

**改法**：补 `gender: birth.gender || cfg.gender || '男'`（`state.js` 的 `BIRTH.gender` 为「男」，`cfg.gender` 兜底），同时透传地点字段；`import` 由 `{ $ }` 改为 `{ $, cfg }`。

## 5【P1】羊刃两表打架 → 全仓一张表（《三命通会》禄前一辰）

**典籍核对**（未照抄任务给的表）：
- 《三命通会·论羊刃》：「羊刃常居禄前一辰……卯者甲之正位、辰者乙之正位、午者丙之正位、未者丁之正位、酉者庚之正位、戌者辛之正位、子者壬之正位、丑者癸之正位」→ **甲卯 乙辰 丙戊午 丁己未 庚酉 辛戌 壬子 癸丑**（十干皆有，禄前一位；与「金舆＝禄前二位」互为印证）。
- 同书《论阳刃》另有「惟甲丙戊庚壬五阳干有刃，乙丁己辛癸五阴干无刃」——那是**阳刃格**的取格之说，不是「羊刃」这条神煞。旧 `shensha.ts` 注释把两句混用，才出现「自称禄前一位、实际给乙寅」的自相矛盾（乙寅是阴干逆行帝旺位，不是禄前）。

**改法**：`shensha.ts` 的 `YANG_REN` 改为上表并 `export`；`bazi-extra.ts` 删除本地同名表，改为 `import { YANG_REN } from './shensha.js'`（单向导入，无环：shensha 只依赖 constants/types）；羊刃 `refs` 由 `['日干','年干']` 收窄为 `['日干']`，`note` 重写并指向共享表。

**实测**：

| 项 | 修前 | 修后 |
|---|---|---|
| 144 组（12 日支 × 12 月支）穷举 | — | 覆盖 **144/144**，目标支错 **0**，年干来源多报 **0** |
| 抽样盘含「年干羊刃」多报 | **1178 / 5460 = 21.58%**（按旧 `refs=['日干','年干']` 口径逐盘复算） | **0 / 5460** |
| 六爻神煞层 | 乙寅 丁巳 己巳 辛申 癸亥 | 乙辰 丁未 己未 辛戌 癸丑（5 个阴干全部改动） |

**连带**：`test/golden.test.ts` 金标准「乙丑日 神煞 14 项」原写 `yangRen: '寅'`（旧金标准 App 的阴干帝旺说），与新表冲突，改为 `'辰'` 并加注 —— 这是全量回归里唯一需要动的**越界文件**（不在任务给的「可改」清单内），原因见 §7。

## 6【P1/P2】天乙 note、空亡显示、偏旺文案

1. **天乙 note**（`bazi-extra.ts:202`）：原写「《渊海子平》原文作『甲戊兼牛羊……庚辛逢马虎』，则庚见午寅、辛见丑未」——两半都错。原文「庚辛逢马虎」是**庚辛同取午寅**，与「甲戊兼牛羊」对举，辛根本没有丑未之义。改为：「则甲戊同取丑未、庚辛同取午寅（庚不复取丑未，辛亦非丑未）；本盘从《三命通会》通行本『甲戊庚牛羊……六辛逢马虎』，庚并取丑未」。
2. **空亡显示**：`ShenShaRef` 增加 `'日柱'`，空亡命中改 `ref: '日柱'`、`refValueOf('日柱')` 返回整柱干支；`baziview.js` 渲染时对空亡只显示干支。修前 chip 文本 `空亡 日支丙申→…`（把整柱挂在地支名下），修后 `空亡 乙卯→子·月`（真实浏览器实测）。
3. **偏旺文案**（`verdicts.js:229`）：`喜财（克我）` → `喜财（我克）`（财是日主所克，原文案与同句「官（克我）」自相矛盾）。
4. 顺带：`baziview.js` 里「旧卡月令生克方向反，待修」的红字说明改为「两处旺衰公式已分叉，请报修」（§1 修好后该分支正常不再触发，留着只作漂移告警）；引导文案里「阴干有没有羊刃」的流派例子换成「天乙贵人庚辛取午寅还是丑未」，因为羊刃已统一。
