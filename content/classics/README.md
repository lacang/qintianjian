**内容源文件、构建脚本、Schema、审核报告、产品数据全部进版本控制**，与产品代码同仓同版本——发布时内容版本和代码版本天然对应，内容修正可回溯，线上出问题能准确定位回滚。

## 一条命令重建

在**仓库根目录**（`每日六爻/`）执行：

```bash
bash content/classics/_build/run_all.sh
```

八步，约 0.2 秒：

| 步 | 脚本 | 做什么 |
|---|---|---|
| 0 | `parse_md.py` | 研究文档 md → `parsed/lunyu.json`（唯一事实源） |
| 1 | `build_nodes.py` | 拼人工核定元数据 → `_build/_nodes_raw.json` |
| 2 | `build_network.py` | 生成群与关系边 |
| 3 | `review_relations.py` | 关系边审核固化（verified/pending/rejected） |
| 4 | `build_content.py` | 拼总包 `data/lunyu-content.json` |
| 5 | `patch_context.py` | 补前后文、计算抽签池 |
| 6 | `fix_p0.py` | P0 硬错误修正 |
| 7 | `validate.py` | 校验（不过就失败退出） |

导出到产品：

```bash
python3 content/classics/_build/export_web.py   # → app/js/classic/lunyu-data.js
```

**不要手改 `data/*.json` 和 `app/js/classic/lunyu-data.js`**，改 `02_思想单元候选总表.md` 后重跑。

## 数据来源与可复现

原典不靠"我记得是这样"，靠可追溯。

`raw/SOURCES.json` 记录每个数据集的：名称、上游地址、下载 URL、许可、许可说明、记录数、SHA256、落盘路径。

| 数据集 | 许可 | 用途 |
|---|---|---|
| `gujilab/chinese-classical-corpus`（原 zi6me） | CC0-1.0 | 十三经及先秦两汉经部文献，按篇/卷存储，`content` 内按换行分章 |
| `NiuTrans/Classical-Modern` | MIT（数据集） | 327 本古文，97 本有句级双语对齐 |
| `garychowcmu/daizhigev20`（殆知阁） | 公有领域 | 1.6 万种典籍，20 亿字，4.8GB |

**52MB 的 `raw/_cache/` 不进 git。** 复现：

```bash
python3 content/classics/_build/fetch_corpus.py
```

下载后自动校验 SHA256，不符则失败退出。

### 三条不能混为一谈的许可

数据集许可（CC0 / MIT）覆盖的是**数据集的组织与标注**，不等于：

1. 底层古籍文本的版本权利状态（通行整理本有标点、校勘、分段，可能另有权利）；
2. 现代译文的授权。**译文权利状态不明的，一律不作为产品内容**，只作为内部参考并标注来源待核。

殆知阁 4.8GB 不整体索引，只按需抽子集（十三经注疏、朱熹《四书章句集注》、王弼《老子注》、郭象《庄子注》）。

### 《论语》有两套分章系统

总数都是 512，篇内分布不同：

| 篇 | 朱熹《集注》本 | 杨伯峻《译注》本 |
|---|---:|---:|
| 雍也 | 28 | 30 |
| 述而 | 37 | 38 |
| 宪问 | 47 | 44 |

**本库用杨伯峻一系。** `split_chapters.py` 自动识别数据集用哪套，差异写进 `raw/reports/split-lunyu.md`。

这不是谁对谁错——章号直接影响产品显示「雍也第几章」，所以必须记录而不能抹平。

## 质量层级（A/B/C）

层级在**产品上必须明示**——不能让用户以为所有内容都经过同等深度的学术考证。

| 层 | 定位 | 核心要求 | 关系边 |
|---|---|---|---|
| **A 深度层** | 值得深入探索 | 原典、语境、注家分歧、充分证据、可追溯关系 | 有依据则展示，**没有就留空** |
| **B 标准层** | 可以独立阅读 | 原典、五要素、注疏依据、现代解读 | 至少一条经审核的关系，**或明确标「暂无可靠关联」** |
| **C 简释层** | 提供基本理解 | 原典、出处、白话、一条注疏 | 不要求 |

**A/B/C 不是内容的等级排名，是证据与解释深度的真实说明。**

关系边数量**不作为硬性准入条件**——硬指标会反过来逼着生产者凑关系。宁可入口为空，也不编造关联。

C 层不得有 `evidence.academic`（`validate.py` 硬校验）。

## 关系依据三层严格分离

| 层 | `relation_basis` | 含义 |
|---|---|---|
| 原典事实 | `canon` | 原典自带判语 |
| 注家解释 | `commentary` | 注家明确合观 |
| 编辑比较 | `editorial` | 本产品建立的对照 |

**跨经典关系一律不得标 `canon`**——没有哪部原典自带跨书判语。孟子性善与荀子性恶可以建立对照，但那是编辑建立的对照，不能包装成古人之间的思想关系。

`editorial` 默认不得 `verified`；人工批准须有 `approved_by` + `review_note`。`rejected` 不物理删除，保留审校记录。

**搜索结果是候选证据，不是已核实证据。** 自动召回可以，但不能因为搜到某段注释就判定它支持某个关系。
