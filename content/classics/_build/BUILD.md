# 注疏索引 构建与复现说明

**状态：P1 完成（2026-11-02 验收通过）。**
本文件说明这一版索引由什么生成、怎么复现、复现到什么程度算通过。
机器可读版本见 `raw/commentary/index/BUILD-RECORD.json`（含每个输入输出的 SHA256）。

---

## 一、这一版是什么

注疏索引把 12 部注本的经、注、疏切成条目，每条挂靠到独立原典，并标明「对齐到什么程度」。

**它不是校勘成果。** 条目数量、`no_canon = 0` 都不代表文字已经校对过。
当前正确状态是 `verified_by` 全空——检索命中不等于证据成立。

```
条目总数          15445
空壳条目          0
verified_by 非空  0        ← 正确状态，不是待消除的缺陷
源文件 SHA256     12/12
原典 SHA256       6/6
抽检 fails/warns  0 / 0
```

状态分布：

| status | 条数 | 含义 |
|---|---|---|
| `ok` | 7879 | 用原典句子做锚，已按原典切分 |
| `self_contained` | 6537 | 经文取自注本自身，未与原典交叉校验 |
| `ok_variant` | 958 | 跨传本系统，章次对应而文字不保证一致 |
| `chapter_level` | 70 | 章次已挂靠，未做文字比对 |
| `jizhu_supplement` | 1 | 朱子补传，`in_canon = false` |
| `no_canon` | 0 | — |

## 二、构建链

```
_build/split_chapters.py          原典切分 → parsed/canon/*.json
        ↓
_build/build_commentary_index.py  注疏索引 → raw/commentary/index/commentary-index.json
        ↓
_build/verify_alignment.py        抽检 + 异文台账 → variant-ledger.json
        ↓
_build/make_variant_worklist.py   注疏层核校工作单 → variant-review-worklist.md
        ↓
_build/build_laozi_variant_ledger.py  老子两传本台账 → laozi-variant-ledger.json
        ↓
_build/make_laozi_review_sheet.py 老子核校工作单 → laozi-variant-review-sheet.md
        ↓
_build/freeze_build_record.py     固化本记录 → BUILD-RECORD.json
```

最后一步把前四步的产出全部纳入指纹（5 个输出 + 8 个脚本），
少记一个产物，构建记录就会漏掉一条「这版是从哪来的」的证据。

`_build/cn_norm.py` 是前两步共用的归一表。**共用一份是刻意的**：切分器和索引各写一份繁简表必然慢慢漂移，最后出现「同一个字切分器能对上、索引对不上」这类极难查的 bug。归一必须 1 字符 → 1 字符，否则锚点索引映射会失效。

## 三、复现

```bash
cd content/classics/_build
python3 build_commentary_index.py
python3 verify_alignment.py        # 必须 fails=0 warns=0
python3 make_variant_worklist.py
python3 build_laozi_variant_ledger.py
python3 make_laozi_review_sheet.py
python3 freeze_build_record.py     # 写记录（自比，证明不了什么）
python3 freeze_build_record.py --check   # 拿记录里的指纹比当前产物，这一步才算校验
```

`--check` 跟 `freeze` 不是一回事：`freeze` 是「把当前文件的 sha 记下来」，刚写完当然一致；
`--check` 是「拿上一次记的 sha 比现在的文件」，产物被手改过、或构建不可复现，只有它看得出来。
实测：把 `laozi-variant-ledger.json` 里一个 `confirmed` 改成 `true`，`--check` 立刻报不一致并退出 1。

`freeze_build_record.py` 会回读校验：如果记录的输入指纹与实际文件不一致，它直接报错退出。**记录本身不可信时不许静默通过。**

### 确定性是「可复现」的前提

全链跑两遍，五个产物的 SHA256 必须逐字相同，否则构建记录里写的指纹只是「某一次跑出来的样子」。

踩过的坑：`build_commentary_index.py` 里 `for cid in set(CANON_CLASSIC.values())`
决定 `canon_sha256` 的键序，而 `set` 迭代顺序受 `PYTHONHASHSEED` 影响——
同一个底本每次产出不同 SHA256 的文件。改成 `sorted(...)` 才稳定。

修完后连跑三次，索引 SHA256 一致。`BUILD-RECORD.json` 自身含 `generated_at`，
整文件 SHA256 每次都会变；**比对要看 `inputs` / `scripts` / `outputs` 三段，不看整文件。**

## 四、对齐是怎么做的（改之前先读这段）

比对归一有三个必要条件，缺一条就大面积对不上：

1. **去引号** — 集注与通行本引号用法不同，引号一参与匹配就错位到几百字外
2. **去标点** — 原典是标点本，注本多无标点或标点习惯不同；整句锚带标点必然找不到
3. **繁简归一** — 注本多为繁体

三条都是 1:1 字符替换，所以「锚点串位置 → 原文位置」的映射保持精确。

另外两条经验：

- **短锚必须局部搜索**。`王曰`、`寡人有疾` 这类 4-5 字小句在一卷里出现多次，全库 `find` 会命中几百字外的另一次，把 `cursor` 推错，后面所有长锚连锁失败。`SHORT_ANCHOR = 6` / `LOCAL = 400`。
- **结构重排必须按映射逐章对齐**。朱子本把古本第 4 段移到第 7 段后，线性扫描的单调 `cursor` 会被顶死。大学走 `parse_mixed_by_plan`，按 `_structure.mapping` 逐章切块、每章 `cursor` 归零。

## 五、验证判据：拿什么证伪 canon_text

**canon_text 的来源决定拿什么证伪它**，这一条弄错会把异文当错误。

| status | canon_text 来源 | 证伪方式 |
|---|---|---|
| `ok` | 独立原典 | 必须能在 `parsed/canon/<classic>.json` 找到 |
| `self_contained` | 注本自身 | 必须能在注本找到（先剥 `（…）` 夹注） |
| `ok_variant` | 跨传本系统 | 只要求注本里能找到，**不拿原典证伪** |

**原典对得上、注本对不上的是异文，不是错误**，进 `variant-ledger.json`。

比对时按小句逐句查，不要求整串连续——注本把注文插在经文中间（`孟懿子问孝。（孔曰：…）子曰：无违。`），整句在源文件里本来就是断开的。

## 六、异文台账

`variant-ledger.json` 142 条，`confirmed` 全为 `false`。

每条带 `entry_id` / `source_file` / `loc_start` / `loc_end`，能直接跳到索引条目和源文件行。
62 组是同一处差异被多个注本命中，用 `group_id` 串起来。

`diff_type` 和 `variant_scope` **刻意留空**。差异类型属于版本学判断——自动猜「字形相近所以是异体」会把真异文误判成排印差异。这一步必须人工。

线索 → 人工核校 → 可引用证据，三段不能合并。

### 老子两传本台账（`laozi-variant-ledger.json`）

这是**另一类台账**，跟上面 142 条不是一回事：上面是「注本引的经文与原典对不上」，
这里是「两个原典传本之间写法不同」。两侧都是原典，不存在谁对谁错。

| 侧 | 版本 | 角色 |
|---|---|---|
| A | 河上公系统正统道藏本（Kanripo KR5c0045 / ZTDZ） | 独立原典 |
| B | 王弼本（道德真经注，魏王弼） | 另一传本系统 |

章次对应，文字不保证一致，两侧不得互相冒充。

**B 侧经文不从索引里取。** 索引里 `laozi-wangbi-daozang` 的经注切分是 `assumed`
（排版交替规律），第 20 章就错位了：199 行注文结尾「益之则」、200 行
「忧。故续凫之足…」是它的续行，多出一行之后整章经注颠倒，B 侧混进大量注文，
拿来对照会造出一堆假异文。

所以 `build_laozi_variant_ledger.py` 直接重读源文件，按三步抽经：

1. **合并续行**——行末是「则/而/以/故/若/其/於…」这类悬空虚词，说明这句没说完。
   不能用「行末有无句末标点」：经文也常以逗号收尾（「我独怕兮其未兆，如婴儿之未孩，」），
   那样会把经文并进注文。
2. **交替位判经文 + 覆盖率否决**——章内奇数位是经文，但与河上公本重合度低于 0.45
   的判为注文剔除。短行（「生之，」）不受比例门槛，只要求至少一字能在原典里找到。
3. **注文位补漏**——注文占两行时交替整体错位，末尾真经文会落到注文位上。
   重合度 ≥0.85 且 ≥8 字（或 ≥0.99 的短行）补回。门槛必须高：
   注文常整句引用经文（「可得而亲，则可得而疏也」重合度 0.80），门槛低了会把注文补回来。

覆盖率**只用来否决，不用来确认**。第 20 章注文「若无所宅」含「若无所」
（出自 A 侧「乘乘兮若无所归」），重合度 0.75，比真经文还高；拿它当确认判据会把注文扶正。
当否决判据则安全：注文整段在原典里找不到，重合度远低于阈值。

结果：81 章抽经覆盖率均值 0.953、最低 0.818。第 10、16、38、41、81 章仍有行被判为
注文剔除，这些章的 `chapter_quality.rejected_as_note` 会标出来，经注边界须人工确认。

台账分两层：条目级（`items`，带 `ledger_id`）用于逐条核校；
章级（`chapters`）给出每章 A/B 全文、本章全部差异块、B 侧抽经质量，
因为「逐章对照」是人工核校的实际工作方式。

同章内「A 写法、B 写法」完全相同的差异块会合并并记 `occurrences`。
第 33 章河上公本每句末都有「也」、王弼本没有，逐字 diff 出 8 条，
台账被虚词淹没，真正的字词异文反而看不见。

差异块超过 12 字的不进异文台账，单列为 `length_diff_suspect`：
多半不是「一字一词的异文」，而是整句归属不同、脱衍，或 B 侧切分有偏移。

#### 全量核校（181 条，`laozi-variant-review.json`）

181 条全部过了一遍。生成 `review_laozi_full.py`，检查 `check_laozi_review.py`
（25 项判据，同样来自裁决要求而不是生成脚本的自证）。

**先重算差异核，不能拿原台账的差异片段当核。** 逐字 diff 的区间边界受两侧共同
文字影响：`矣故有无之 / 已故有无` 里真正的差异只是「矣→已」和一个「之」的有无，
其余「故有无」两边一样。把整段当差异，人判的时候被无关字干扰，
「等长替换」和「脱一字」也会混成一类。

做法是两级对齐：先章级对齐定位差异块（复用台账构建时的 `merge_blocks`），
再在块内对 `a_seg / b_seg` 做一次 `SequenceMatcher`，取全部非 equal opcode 作最小核。
181 条全部对齐成功，`LV-0001` 得到 `矣→已` + `之→∅` 两个核。

**证据分三级，只有 strong 才 `confirmed`：**

| 级别 | 判据 | 能证明什么 |
|---|---|---|
| `strong` | 全书用字对 ≥3 例；或录入字体层可直接验证 | 两传本用字习惯不同 |
| `medium` | 用字对 2 例；语序回查命中；多字片段在对侧全文确无；B 侧注文复述 | 两侧确不同，但未见影印页 |
| `none` | 只有「两侧不同」这一个事实 | 无独立证据，待考 |

`confirmed` 只说「差异性质已确认」，从不说「某版本正确」。
本轮不写 `confirmed_by` —— 归类是 Agent 做的，签字得主人来。

**四项自动取证各自管一段：**

1. **全书用字对**——同一对单字在全书出现几次。`惟/唯` 15 例（章 8、15、21、22、
   41、42、53、59、67、70、71、72、75）、`处/居` 3 例、`人/民` 4 例、`民/人` 3 例。
   出现多次说明是两传本系统性用字差异，不是某章孤立讹误。
2. **语序回查**——多字 delete 片段若在对侧**同章另处**出现，就不是脱文，是次序不同。
   `LV-0130` 的「无事而民自富我」在 B 侧 57 章位置 75，A/B 只是「自富」「自正」互换。
3. **源文件回查**——多字片段在对侧全文确无，才敢说「两侧文本确不同」。
   但这不等于「王弼原书无此句」，那要影印页。
4. **注文复述**——注文含差异字前后 3 字窗口，说明注文与经文用字一致，弱证据。
   `LV-0014`「阖能为雌乎」、`LV-0073`「亦既有夫亦将知」、`LV-0118`「甚芜仓甚虚」等 6 条。

**新增 `error_source = font_normalization`（录入字体层差异）。**
两侧源文件都经过简体化处理，但 A 侧（KR5c0045）部分生僻字未简化、B 侧已简化：
`頑/顽`、`渾/浑`、`倉/仓`、`張/张`、`类/颣`。这是录入字体层差异，
两传本此处在字上并无不同，**不构成传本异文**。单独立类，不混进 `orthographic_variant`。

**影响程度五级**（`impact`）：`font`（字体层，非异文）/ `orthography`（异体通假）/
`syntax`（虚词增删、语序）/ `lexical`（字词，义近）/ `meaning`（实词，涉及义理）。

**本轮分布：**

| 项 | 条数 |
|---|---|
| 差异形态 `char_level` / `omission` / `mixed` / `addition` / `word_order` | 104 / 40 / 35 / 1 / 1 |
| 来源 `orthographic_variant` / `textual_variant` / `unknown` / `font_normalization` | 41 / 42 / 95 / 3 |
| 证据 `strong` / `medium` / `none` | 25 / 13 / 143 |
| 状态 `confirmed` / `pending` | 25 / 156 |
| 需人工逐条复核 `needs_human` | 72 |

**143 条 `none` 不是没做，是没有第三方版本可比。** 老子这两个传本之外，
本轮没有引入第三种版本（帛书、竹简、傅奕本等），所以「两传本不同」之后
能再往下判的依据很少。把 143 条写成「已确认异文」才是造假。

其中 72 条 `needs_human = true`（实词、字词类，判不了就是判不了）；
另 71 条 `needs_human = false` —— 虚词增删（`impact = syntax`）性质是清楚的，
两传本虚词出入是常见现象，缺的只是「哪个是原本」的第三方版本，不必逐条占人工。

**老子 181 条与注疏层 142 条不能合并统计。** 前者是「两个原典传本之间写法不同」，
后者是「注本引的经文与原典对不上」，两类问题的证据链完全不同。

#### 结论回写：追加式，两层不互相覆盖（`apply_laozi_review.py`）

核校结论回写进 `laozi-variant-ledger.json` 的 `review` 子对象，**顶层原始字段一个不动**。

| 层 | 字段 | 记什么 |
|---|---|---|
| 候选层（顶层） | `differs` / `wangbi_side` / `canon_snippet` / `occurrence_locs` / `diff_type` / `confirmed` | 程序在源文件里发现了这处不同。事实不随结论改变 |
| 结论层（`review`） | `diff_core` / `error_source` / `impact` / `evidence_level` / `evidence` / `status` / `confirmed` / `needs_human` | 后来判成了什么、凭什么 |

**为什么不能把结论填进顶层 `confirmed`**：填进去，原始候选就被改造成了结论，
以后再也分不清「当初发现了什么」和「后来判成了什么」。回写后顶层
`confirmed` / `diff_type` / `verify_note` 仍然全为空，这是检查项，不是遗漏。

`review.confirmed` 的语义被写死在数据里：`confirmed_scope = "difference_nature"`。
它只表示差异性质已确认，**不表示 A 本或 B 本更接近原本，也不表示两边文字已经匹配上**。
`confirmed_by` 全为空——归类是 Agent 做的，签字得人来。

回写后的口径（`stat.review`）：

| 项 | 值 |
|---|---|
| `reviewed` | 181 |
| `confirmed` / `pending` | 25 / 156 |
| `needs_human` | 72 |
| `font_layer_excluded` | LV-0031、LV-0118、LV-0171 |
| `in_variant_ledger` | 178（181 − 字体层 3） |

**字体层差异不计入异文总量。** 以后做跨版本比较、统计「两传本差异有多少处」时，
必须把 `font_normalization` 排除出去——否则数字化处理造成的差异会把真实异文数量撑大，
做出来的是一份看起来完整、实际不断制造错误的版本比较。

**71 条虚词增删 `needs_human = false`，但仍然是 `pending`。** 不逐条占人工，
不等于已经确认。`status` 只有 `confirmed` / `pending` 两个值，没有「默认算过」这一档。

### 人工核校写回（batch01：前 20 组）

前 20 组已由主人逐组裁决并写回。写回脚本 `apply_review_batch01.py`（幂等），
结构检查 `check_review_writeback.py`（写回脚本自检等于没检查，判据来自裁决要求）。

**新增 `error_source` 字段，不改 `diff_type` 的语义**。两者是不同维度：

| 字段 | 记什么 | 取值 |
|---|---|---|
| `diff_type` | 文本差异长什么样 | char_level / omission / addition / word_order / structure |
| `error_source` | 这个差异该归到哪一类来源 | 见下 |

```
textual_variant        古代传本之间确实存在的文字差异
orthographic_variant   异体字、通用字
phonetic_loan          通假、借字、古今字（有注音证据）
commentator_error      注本自身讹误
ocr_defect             数字化过程产生的缺字、错字
source_excerpt_issue   材料截取或窗口不全，暂不能当异文
mixed                  同一组内混有两类问题，拆 sub_issues
unknown                材料不足，待考
```

这四类东西混在一起，做出来的就是一个看起来很完整、实际不断制造错误的数据库。
**宁可留下待考，也不要让程序替古人定字。**

batch01 分布（40 条线索 = 20 组 × 2 注本）：

| 状态 | 组数 | 条数 | 组号 |
|---|---|---|---|
| `confirmed` 性质可确认 | 6 | 12 | 04、05、06、08、09、18 |
| `pending` 待考 | 10 | 20 | 01、02、03、07、10、11、12、14、19、20 |
| `source_defect` 源文件缺陷（移出异文台账） | 4 | 8 | 13、15、16、17 |

进入异文台账 **134** 条（总 142 − 源文件缺陷 8）。`stats.confirmed` 记台账内的 12 条，
`stats.confirmed_any` 记含缺陷的性质确认 20 条——**源文件缺陷的性质也确认了，但它不是异文，
不能并进 `confirmed` 当异文数用**。

`confirmed` 只代表现有材料足以确认**差异性质或问题归属**，不代表已证明某字为古本原貌。
没看底本影印页的，不写成版本学结论。

`confirmed_scope = "group"` 表示主人按组裁决、组内两个注本同判；
日后单独核校某一注本发现不同，必须拆开——**同组命中不等于同组结论**。

**第 14 组拆成两个子问题**，不合并成一个差异性质：A「餽 / 馈」字形用字差异，
B「七十」后缺「镒」疑似脱字。原条目 `error_source = mixed`、`confirmed = false`，
子问题各自带 `confirmed`，放在 `sub_issues`。

#### 这一层的证据逻辑跟老子不一样，不能照搬

老子那边是**两个不同注家的传本**（王弼本 / 河上公本），「两传本同现」有版本学含义，
所以能用「全书用字对 ≥3 例」当 `strong`。

注疏层这边，一组两条是**同一部朱注的两个电子本**（`mengzi-jizhu` /
`sishu-zhangju-jizhu`），两个文件很可能出自同一数字化底本。因此：

- **两载体一致，不构成独立证据。** 只说明「该差异在这两个电子本里都存在」，
  不说明「朱子本原本如此」。同一处脱字两个文件一起脱（`VG-012` 脱「身」），
  恰恰说明它们同源，不能互证。
- 本批可用的 `strong` 判据只有三类：**字形可直接对照**（异体字）、
  **空位可直接观察**（缺字）、**注文自证音义**（朱注自己给这个字注了音或训释）。
- 门槛比老子低一档：不需要跨章统计，只要差异在电子文本内部就能验证。

#### 三类新发现，各自的处理

**① 注文错位造成的假差异（`digital_defect` → `diff_type = segmentation`）**

`VG-052`：注本侧「耆，与嗜同，下同」这条注文错排在「是天下之口相似也」之后，
把经文切成两段，程序按连续片段比对就报出差异。两侧经文实无不同。
这类**不是异文**，`impact = none`，不能进异文总量。

**② 整段缺文（`source_defect`）**

`VG-048`：注本侧「舍，日暴之，十日寒之」——经文「孟子曰：无或乎王之不智也。
虽有天下易生之物也，一」整段缺失。同章下文注文有「犹一日暴之也……是十日寒之也」，
说明**朱注所见经文本来有这一整段**，缺的是电子本，不是朱注本。

**③ 注文钉住缺字（`source_defect` + 注文自证）**

`VG-025` 注本作「 尔而与之」，首字空位；其下注文「 ，呼故反」同样空位——
注音「呼故反」正对「嘑」，丢的字被注音钉死了。
`VG-028`「播?武」的「?」同样由注文「徒刀反」「小鼓」钉住为「鼗」。
`VG-010`「以杖荷莜」不是缺字，注文「莜，徒吊反」证明注本读的是「蓧」，
属同字异写。

**`source_defect` 的 `confirmed` 只表示「这个电子本此处缺字」**，
不表示刻本缺字，更不表示传本脱文。这一条写进每条的 `verify_note`。

### 源文件缺陷与传本异文必须分开记

`source-defect-ledger.json` 记的是「数字化过程把字弄丢了」，不是「古人写的字不一样」。

**两种 kind，共用一套结构，kind 决定必填字段：**

| kind | 含义 | 必填 |
|---|---|---|
| `missing_char` | 单字或少量字符缺失 | `char_expected` / `char_present` |
| `missing_passage` | 连续文字或整段缺失 | `anchor_before` / `anchor_after` / `expected_text` / `estimated_missing_chars` |

两者都是数字化文本质量问题，但修复、定位和验证方式不同，不能用一个笼统的「缺字」描述糊过去。

`expected_text` 一律带 `expected_text_is_inferred = true`——它是根据现有证据推定的待核文本，
不是已核实的原始底本文字。`estimated_missing_chars` 是估算值，不作精确校勘字数使用。

**SD-0001（`missing_char`）**：`蚔鼃` / `蚔␣`，第 15/16/17 组三条同源合并。
独立证据是注本自注「蚔，音迟。␣，乌花反」——「乌花反」正是「蛙」的音。
不是根据上下文猜缺字，是注本自己留下了读音信息。同一行三处出现，`occurrences` 都记下来。

**SD-0002（`missing_passage`）**：第 13 组「出吊于东郭氏」。回查 L46–L62 确认：
L48 单行 1311 字，原文作「孟子亦以疾辞也。明“昔者辞以病，今日吊，或者不可乎？”」，
「明」后直接接引号，缺「日，出吊于东郭氏，公孙丑曰：‘」（推定 12 字）；
同行注文仍释「东郭氏，齐大夫家也」「辞疾而出吊」，经文与注文不匹配。

判断依据四条：① L48 确实存在经文缺失 ② 「明」后直接出现引号，语句结构不完整
③ 同行注文仍解释东郭氏和出吊，形成内部证据 ④ 缺失属原文叙述，不是注家有意省略的普通注文。

**可确认的是源文件缺失，不是原始底本如何排版。** 没看底本影印页，不写成版本学结论。

处理方式：
- 从传本异文台账移出（`status = source_defect`，统计上不计入 `in_variant_ledger`）
- `diff_type` 置 null——源文件缺陷不是传本异文，不套用异文形态分类
- 原始条目保留，`moved_to` 指回缺陷记录，历史痕迹不删
- 缺陷记录留 `fix.before / fix.after / fix.basis` 三格，`status = open` 时全为 null，
  修复时才填。open 状态填了 fix 会被结构检查拦下
- **归一表要不要补这个字，是独立任务**：原典存在一个字，不代表归一表必须收录；
  归一表漏字，也不代表原典出现版本异文。不要让归一表问题污染版本学台账

### 源文件修复不等于传本校勘（长期规则，已写入 AGENTS.md 4.3）

修复 OCR 时：原始文件保留；修复后的文件有独立版本；每次记录前后文本；
记录修复依据及人工核校人；**不允许修复后的文本覆盖原始来源证据**；
修复完成后重新构建索引，验证关联条目和指纹。
尤其不能把程序推测的缺失文字直接写入原典层。

注本侧定位逻辑在 `locate_snippet.py`，工作单和核校批共用一份。
两处各写一套，改了一处忘了另一处，同一组线索在两个文件里会定位到不同句子。

定位踩过三个坑，别再走：拿差异片段本身搜（它是原典写法，注本这里是另一个字，永远搜不到）；
拿差异片段两侧当双锚（原典「出吊于东郭氏」，注本这一章另有「出吊于滕」，
「出吊于」四字命中到不相干的另一句，**人对着错句判比不给位置更糟**）；
拿 canon_text 当锚（按小句切，短句只剩 4 字公共部分）。
现在用最长公共子串，阈值 4 且要求该块在章内不重复。定位失败就明说失败，
由人按行号回源——不拿章首冒充位置。

全量工作单的窗口是差异点前后各 110 字（便于看整段上下文），
核校批收到 40 字（便于在聊天窗口里逐组读）。窗口大小不改变证据——
源文件行号照给，要看整章随时回源。

**一个窗口有时不够**。注本会把一句经文拆开排：论语集注「孔子于乡党，恂恂如也，
似不能言者。」与「其在宗庙朝廷，便便言，唯谨尔。」之间隔着几百字注文。
主窗口以差异点为中心，只覆盖得到前半句，差异落在注文之后，人看不到——
看到的是一段注文加半句经文，判不了。

所以 `locate_all` 在主窗口之外，检查原典句尾部是否落在窗口内，不在就补第二个窗口，
两个窗口用「／」分开并列。取尾部时**必须从差异片段之后取**：第 6 组差异是「庭 / 廷」，
直接取尾部 8 字得「朝庭便便言唯谨尔」，注本写的是「朝廷」，整串永远搜不到。
从差异之后取，得到「便便言唯谨尔」，两侧相同，搜得到。

补窗口不能用「差异点线性推算」再定位一次——注本拆开排导致前后偏差几百字，
推出来的位置还是落在注文里。直接用尾部文字在章文里搜，命中即真实位置。
**宁可多给一段，也不让人对着半句话判。**
