## 三、选条标准（4 进 1 出）

### 四条入选理由，每条至少满足两条

1. **补篇**：该篇目前 0 条。7 个空白篇优先。
2. **补主题**：让 8 个主题各 6—8 条**互不重复**（现在是平均重复 3 次）。
3. **大众熟知**：用户看到会「哦这句我知道」——这是他愿意点进去的第一动力。
4. **思想可展开**：不是单句格言，有可指认的对话场合、可对照的注家分歧。

### 一条排除标准

**争议极大且与现代价值观直接冲突的，不收，或收但必须配纠错 + 分歧并列。**

典型：「唯女子与小人为难养也」。这条大众熟知度极高、误读极多，但裸收会伤害产品气质。处理方式只有两种：要么不收，要么收进来时同时挂一条纠错节点，且原文语境（对话对象、前后文）必须完整呈现。**不允许只放原文了事。**

乡党篇（生活细节，如「食不厌精」）思想性弱，本轮不收，理由写进记录。

## 五、每条要过七道工序（沿用现有标准，不降级）

这是 26 条当初怎么做的，34 条照样做：

| 步骤 | 内容 | 产出 |
|---|---|---|
| 1 | **原文核验**：ctext.org + 中研院 PDF + acmuller.net 三版本对照逐字核 | `original` |
| 2 | **篇章定位 + 前后文**：本章在篇中位置、前章后章是什么 | `location` / `context.before/after` |
| 3 | **上下文五要素**：谁说的 / 对谁说 / 当时在讨论什么 / 前章 / 后章 | `context` 五项，缺一不可 |
| 4 | **四维证据**：大众传播 / 学术研究 / 历史注疏 / 现代关联，**每维至少一条可点开的 URL** | `evidence` |
| 5 | **注家与分歧**：至少两家注疏原文；有学术分歧的**并列呈现，不合成** | `commentaries` / `disputes` |
| 6 | **关系边**：与已有节点的关系，按 `fact_basis` / `relation_basis` / `display_class` 三层记，编辑阐释必须标 `must_label` | `relations` |
| 7 | **产品文案**：`modern`（一句白话直译）+ `think`（60 字左右，落到读者自己的处境） | `reading.js` |

**质检关（`validate.py` 现有硬校验，一条不过全库不通过）**：
- context 五要素非空
- 关系两端存在、`basis` 非空
- `relation_basis == editorial` 不得 `verified`，除非有 `approved_by` + `review_note`
- 抽签池数量与声明一致
- 分片与总包一致

**证据等级允许不齐**：26 条里 strong 只有 5 条、medium 21 条。新增条目按同一标准评，**不为了凑 strong 去编来源**。宁可标 medium，不写假 URL。

## 七、开工前必须先修一个工程隐患（P0）

`_build/build_nodes.py` 第 5 行读的是：

```python
PARSED = json.load(open('/tmp/ly_parsed.json', encoding='utf-8'))
```

**研究文档的解析结果放在 `/tmp`。** 这台机器重启或清理临时目录，整个构建链就断了——`run_all.sh` 第 1 步直接报错，而 26 条数据的研究内容只存在于那个临时文件里（`02_思想单元候选总表.md` 是人读的 markdown，不是机器解析源）。

扩充 34 条之前必须做两件事：

1. 把 `/tmp/ly_parsed.json` 复制进仓库（`_build/parsed/ly_parsed.json`），改路径；
2. 把「从 markdown 生成 parsed json」这一步写成脚本（`parse_candidates.py`），让 `run_all.sh` 从 md 一路可复现到 `data/`。

**否则第一批做到一半，构建链断了，前面所有研究都可能要重做。**
